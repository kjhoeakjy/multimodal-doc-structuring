# v10 표와 이미지에 분산된 정보의 관계와 적용 조건을 보존하는 전처리 및 구조화 방안

작성 2026-10-28

**주제** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**핵심 아이디어** 비정형 데이터의 전체 내용을 우선 추출하고 관계가 누락되거나 불확실한 영역에 한해 추가 분석한 뒤, 분산된 정보와 적용 조건을 연결해 LLM이 활용할 수 있도록 구조화함.

**적용 대상** PDF와 스캔 형태의 기술문서(정비 교범, 시험 기준, 규격). CAD 모델과 구조화된 설계 데이터는 제외함.

**설계 전제** 독립 실행 가능한 오픈소스 모델 활용. 제한된 연산 자원을 고려한 처리. 특정 조직의 시스템과 자원 현황은 전제하지 않음.

## 1. 문제

기술문서의 정보는 한곳에 모여 있지 않음. 체결부가 어느 부품에 속하는지는 그림에, 체결부별 토크 값은 표에, 그 값이 유효한 조건은 각주에 기록됨. 문서를 텍스트로 변환해 일정 길이로 나누면 세 정보가 분리되어 값을 정확히 읽어도 어느 대상에 어떤 조건으로 적용되는지 알 수 없음. 해결할 문제는 문자 인식의 정확도가 아니라 정보 간 연결 관계의 보존임.

## 2. 해결 방안

### 2.1 데이터 전처리

전체 문서를 먼저 가볍게 추출하고 관계 점검에서 문제가 확인된 영역에 한해 추가 분석함. 정보를 선택적으로 추출하는 것이 아니라 추가 분석을 선택적으로 수행하는 방식임.

| 순서 | 단계 | 내용 |
|---|---|---|
| 1 | 전체 기본 추출 | 모든 페이지의 텍스트, 표, 이미지 영역을 확인함. 텍스트 레이어가 있는 문서와 디지털 표는 CPU 파서로 텍스트, 셀, 위치를 추출하고 PDF 도면은 벡터 객체와 좌표를 사용함. 스캔 문서와 이미지는 기본 OCR과 경량 시각 분석(도형, 선, 원 검출)으로 요소와 위치를 확보함 |
| 2 | 구조화와 관계 점검 | 대상, 값, 조건, 출처를 연결하고 누락된 각주, 불명확한 객체 관계, 서로 충돌하는 값을 확인함 |
| 3 | 선택적 추가 분석 | 문제가 확인된 영역에 한해 고해상도 재처리 또는 소형 시각언어모델(VLM)을 적용함 |
| 4 | 저장 | 확인된 정보를 적용 조건과 함께 보존하고 질의 시 재사용함 |

관계 점검의 기준

| 점검 항목 | 판단 기준 | 추가 분석 영역 |
|---|---|---|
| 표의 각주 기호 | 각주 문장이 없거나 각주는 있는데 기호가 붙은 셀이 없음 | 표 영역, 표 하단 |
| 그림과 표의 대응 | 그림에서 검출된 체결부 수와 표의 행 수가 다름. 번호 판독 실패 또는 중복 | 표 영역, 해당 체결부 주변 |
| 식별자 | 표의 식별자가 그림에서 확인되지 않음 | 해당 그림 영역 |

한계: 전체 문서를 한 번 분석했다고 정보가 전부 추출되었다는 보장은 없음. 처음부터 누락된 객체나 잘못 인식된 관계는 관계 점검으로도 발견되지 않을 수 있으므로 원본과의 표본 대조와 중요 정보의 별도 확인이 필요함.

**연산 자원 측면** 모든 페이지를 고성능 멀티모달 모델로 처리하는 대신 전체 자료에는 가벼운 1차 처리를 하고 문제가 있는 일부 영역에 한해 추가 분석함. 비용 절감은 1차 분석 비용, 재분석 비율, 정확도를 함께 측정해 확인함. 페이지당 분석 비용이 작은 OCR 재처리에서는 절감이 성립하지 않을 수 있으며 절감은 페이지당 비용이 큰 VLM 처리에서 의미가 있음.

### 2.2 데이터 구조화

**정보 구조** 대상, 속성 또는 관계, 값, 적용 조건, 출처로 저장함. 단위는 값과 함께 표기함. 출처는 문서명이 아닌 이미지 영역, 표 셀, 각주 단위로 기록해 잘못된 연결의 원본 확인 근거로 삼음.

**표의 연결** 헤더, 셀, 각주의 관계는 문서 구조를 기준으로 연결함. 각주가 규격이나 조건을 명시하면 그 기준으로 해당 행에 연결함.

**그림의 연결** 부품 상자와 체결부 번호를 추출한 뒤 포함 관계로 소속을 확인함. 공간적 근접을 근거로 소속을 확정하지 않으며 경계가 불명확하거나 번호 판독이 실패한 경우 원본과 함께 미확정 상태로 보존함. 식별자는 표기 규칙을 정규화한 뒤 대조함.

**적용 조건의 저장** 각주와 조항 등에 분산된 조건을 해당 값에 연결해 저장함. 동일 대상에 조건별로 다른 값이 있으면 각각 보존함.

**질의 시 전달** 질문의 대상과 조건에 해당하는 값, 조건, 출처를 조회해 전달함. 질문에 조건이 없으면 조건별 값을 함께 전달하고 기록에 없는 조건은 기준이 없음을 전달함.

**연산 자원 측면** 구조화는 문서 등록 시점에 1회 수행해 재사용함. 질의 시점에는 필요한 값과 조건으로 입력을 한정해 소형 로컬 LLM의 입력량을 줄임.

## 3. 사례

가상 정비 문서 기준.

**원본 구성**

- 그림 1 조립도: 부품 상자 4개(부품 번호 표기)와 원 안에 번호를 적은 체결부 8개. 체결부 3은 부품 HV-202 상자 안에 위치
- 표 1 체결부 토크

| 항목 | 규격 | 토크(N·m) |
|---|---|---|
| 1 | M6 | 10 * |
| 2 | M10 | 48 * |
| 3 | M8 | 25 * |

\* 건식 나사산 기준. 윤활 시 M6 8 N·m, M8 20 N·m, M10 38 N·m

**질문** HV-202를 고정하는 체결부의 윤활 조건 토크 값

**필요 정보** 그림의 소속(체결부 3은 HV-202), 표의 규격과 값(M8, 25 N·m), 각주의 윤활 조건 값(20 N·m). 어느 하나라도 누락되면 답변 불가.

**구조화 결과**

| 대상 | 속성 또는 관계 | 값 | 적용 조건 | 출처 |
|---|---|---|---|---|
| 체결부 3 | 소속 부품 | HV-202 | 없음 | 그림 1의 체결부 3 원과 HV-202 상자 |
| 체결부 3 | 규격 | M8 | 없음 | 표 1의 3행 |
| 체결부 3 | 토크 | 25 N·m | 건식 | 표 1의 3행 |
| 체결부 3 | 토크 | 20 N·m | 윤활 | 표 1의 각주 * |

**질문 조건별 전달 내용**

| 질문 조건 | 전달 내용 |
|---|---|
| 윤활 | 20 N·m, 윤활 조건, 출처 |
| 조건 미지정 | 건식 25 N·m와 윤활 20 N·m 병기 |
| 기록 없는 조건 | 해당 조건의 기준 부재. 답변에 필수적인 근거가 없으면 보류 |

**추가 분석 사례** 스캔본에서 기본 OCR이 표의 일부 행과 원 안의 번호 1, 7을 읽지 못함. 그림의 체결부 수(8)와 표의 행 수(6)가 달라 표 영역과 해당 원에 한해 고해상도로 재처리해 행과 번호를 복구함.

## 4. 기존 접근과의 차이

일반적인 구성은 문서를 텍스트로 변환해 일정 길이로 분할한 뒤 검색하거나 페이지 이미지를 그대로 검색하는 방식임. 개별 요소는 2026년 연구에 부분적으로 있으며 이를 기술문서의 그림, 표, 각주 연결에 맞춘 하나의 처리 흐름으로 구성한 점이 다름.

| 구분 | 일반적인 구성과 최신 연구 | 제안 |
|---|---|---|
| 적용 조건 | 각주와 조건을 본문 텍스트의 일부로 처리. 조건부 지식 연결 연구는 의생명 분야 중심(Condition-Gated Reasoning, 2026) | 값마다 적용 조건을 함께 저장. 항공 기술문서 표준 S1000D의 적용성 개념을 그 구조가 없는 PDF와 스캔 문서에 복원 |
| 시각 모델 적용 범위 | 전체 페이지 처리 또는 파싱 품질 기준 재처리(ParseFixer, 2026) | 전체 기본 추출 뒤 관계 점검에서 문제가 확인된 영역에 한해 추가 분석 |
| 그림과 표의 연결 | 그림 설명 텍스트 검색 또는 도면 영역 검색(BLUEPRINT, 2026) | 체결부 번호와 부품 상자의 포함 관계 확인 후 표의 행과 연결 |
| LLM 입력 | 검색된 텍스트 조각 입력 | 질문 조건과 일치하는 값과 출처 전달 |

## 5. 검증

모든 방식은 파싱 결과를 저장해 재사용하는 조건에서 비교함. 기준선은 현업에서 통용되는 방식, 최신 방식은 공개 모델로 폐쇄망에서 실행 가능한 것으로 한정함(후보는 docs/research/구현-후보.md).

| 측면 | 구분 | 비교군 | 지표 |
|---|---|---|---|
| 효율(전처리) | 기준선 | 전체 페이지 OCR, 레이아웃 파서 기본 파이프라인 | 페이지당 처리 시간, 메모리, 추가 분석 영역 수, 미해결 연결 수 |
| 효율(전처리) | 최신 | 소형 시각언어모델(VLM)의 전체 페이지 변환 | 같음 |
| 효율(전처리) | 제안 | 전체 기본 추출 뒤 관계 점검 기준 선택적 추가 분석 | 같음 |
| 효과(구조화) | 기준선 | 고정 길이 분할, 요소 단위 분할(표는 마크다운, 각주 포함), 페이지 전체 입력 | 질의 유형별 정답률, 질의당 입력 토큰 |
| 효과(구조화) | 최신 | 페이지 이미지를 VLM에 직접 입력, 문서 요소 그래프 구축 | 같음 |
| 효과(구조화) | 제안 | 관계와 적용 조건을 연결한 항목 입력 | 같음 |

**1차 결과(합성 문서 20건, 절반 스캔본, 질의 376건, 규칙 판독)**

요소 단위 분할과 페이지 전체 입력은 제안과 같은 추출 결과를 쓰므로 구조화 방식의 차이가 드러남.

| 질의 유형 | 건수 | 고정 분할(일반 OCR) | 요소 단위 분할 | 페이지 전체 입력 | 제안 |
|---|---|---|---|---|---|
| 값 조회 | 160 | 50% | 91% | 91% | 97% |
| 조건 포함 조회 | 160 | 50% | 89% | 89% | 90% |
| 그림 연결 조회 | 28 | 0% | 0% | 0% | 86% |
| 조건 미지정 조회 | 28 | 0% | 0% | 0% | 86% |
| 질의당 입력 토큰 중앙값 | | 273 | 222 | 242 | 46 |

값과 조건 조회는 표와 각주를 한 단위로 묶는 요소 단위 분할로 대부분 해결됨. 그림 연결 조회와 조건 미지정 조회는 페이지 전체를 입력해도 0%이며, 체결부와 부품의 소속 관계가 텍스트에 없고 그림의 위치 관계에 있기 때문임. 제안의 오답 376건 중 보류 24건, 오답 5건(규격 셀 미판독에 따른 부분 답변 4건, 숫자 오판독 1건). 디지털 문서는 제안 100%, 스캔본은 84%. 스캔본 문서당 추가 분석 영역 평균 5.6개, 미해결 연결 평균 1.5건. 합성 문서는 한 페이지가 240토큰 정도라 페이지 전체 입력의 토큰 부담이 실제 교범보다 작게 나타남.

처리 시간은 OCR 기준 재처리라 전체 페이지 고해상도 OCR 한 번보다 길었음. 비용 절감은 페이지당 비용이 큰 VLM 처리에서 다시 측정함. 노트북 측정 항목: 레이아웃 파서 기본 파이프라인과 소형 VLM 전체 페이지 변환의 처리 시간과 메모리, 페이지 이미지 직접 입력의 토큰과 정답률, 소형 LLM 판독 정답률.

## 6. 1장 구성

제목: 표와 이미지에 분산된 정보의 관계와 적용 조건을 보존하는 전처리 및 구조화 방안

| 구성 | 내용 |
|---|---|
| 문제 | 그림, 표, 각주의 정보가 텍스트 변환 과정에서 분리될 위험. 요소 유형별로 우수한 파싱 방식이 상이하다는 연구 결과(ParseBench, 2026) |
| 데이터 전처리 | 전체 기본 추출, 관계 점검, 문제 영역에 한한 추가 분석. 체결부 번호 미판독 재처리 사례로 제시 |
| 데이터 구조화 | 값과 적용 조건, 출처를 연결해 저장(S1000D 적용성 개념). 등록 시 1회 구조화, 질의 시 필요한 값과 조건으로 입력 한정 |
| 사례 | 조립도, 토크 표, 각주의 실제 형태와 LLM 전달 과정 도식. 질문 조건별 전달 내용은 한 줄 |
| 검증 | 질의 유형별 정답률, 질의당 입력 토큰 수, 문서당 처리 시간. 합성 문서 기준임을 명시 |

모델명, 모델별 성능 수치, 하드웨어 사양, 저장 구조, 특정 내부 업무와 시스템은 기재하지 않음.

| 예상 질문 | 답변 요지 |
|---|---|
| 처음부터 빠진 객체는 어떻게 찾는가 | 관계 점검으로는 찾지 못함. 원본과의 표본 대조와 중요 정보의 별도 확인으로 보완 |
| 래스터 도면의 도형 추출 신뢰도 | 소형 문서 모델의 레이아웃 인식 성능은 제한적(Granite-Docling 모델 카드 기준 mAP 0.27). PDF 도면은 벡터 객체와 좌표를 우선 사용. 실패 시 미확정으로 두고 사람 확인 |
| 식별자 표기 불일치 | A-17, A17, A-17-01과 OCR 혼동(I와 l)을 표기 규칙으로 정규화한 뒤 대조. 해결되지 않으면 미확정 |
| 문서 버전 혼재 | 출처에 문서 버전 포함. 서로 다른 버전의 표와 그림은 연결을 확정하지 않음 |
| CPU 전용 환경 | 소형 문서 모델도 CPU에서는 쪽당 수십 초 수준으로 대량 처리에 부적합. GPU 1장 수준 필요 |
| 연산량이 실제로 줄어드는가 | OCR 재처리에서는 줄지 않음. 페이지당 비용이 큰 VLM에서 1차 비용, 재분석 비율, 정확도를 함께 측정해 판단 |
| 재처리 검증 방식 | 추출 결과를 원본 영역에 다시 렌더링해 대조하는 방식(RaV-IDP, 2026)을 보조 수단으로 활용 가능 |
