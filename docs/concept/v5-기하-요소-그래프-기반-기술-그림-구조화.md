# v5 기술 그림의 관계 그래프 기반 구조화 및 LLM 연계

작성 2026-10-29. 세부 설계, 근거, 실험은 [v5-상세.md](v5-상세.md).

**주제** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**전제** 생성형 VLM 미사용. 폐쇄망, 제한된 GPU, 기존 텍스트 LLM.

## 문제

기존 OCR과 RAG는 그림의 문자는 추출하나 연결, 위치, 지시 관계를 잃음. 회로도에서 "Valve A", "Pipe 1", "Pump B"라는 문자는 남고 어느 것이 어디에 연결되는지는 사라짐. 멀티모달 모델의 도면 실패도 문자 판독이 아니라 요소 간 관계에서 발생함(AECV-Bench 2026, MechVQA ICML 2026).

## 해결책

기술 도면과 도식(설계도면, 회로도, 계통도, 그래프, 표)의 시각 요소를 원본 파싱과 경량 비전 모델로 추출하고 요소 간 관계의 그래프로 구조화함. 질문과 관련된 부분 그래프를 텍스트로 기존 텍스트 LLM에 전달함.

| 단계 | 처리 |
|---|---|
| 1. 시각 요소 추출 | PDF, CAD 직접 파싱. 스캔은 OCR과 선, 기호 인식 |
| 2. 관계 그래프 생성 | 객체, 문자, 기호를 노드로. 연결, 포함, 지시 관계를 간선으로 |
| 3. 근거 연결과 검색 | 노드마다 원본 좌표 보존. 그래프 텍스트 검색과 이미지 임베딩으로 관련 그림 검색 |
| 4. 기존 텍스트 LLM | 질문 관련 부분 그래프를 텍스트로 전달. 답변에 근거 좌표 첨부 |

```
Valve A --connected_to--> Pipe 1
Pipe 1  --connected_to--> Pump B
```

연결 관계는 선과 접점 분석으로 확인함. 객체가 가깝다는 이유로 연결로 판정하지 않음.

## 경쟁 포인트

그림의 시각 요소를 추출하는 데 그치지 않고 요소 간 관계를 기존 텍스트 LLM이 활용할 수 있는 공통 구조로 변환함. 서로 다른 기술 도식의 관계 정보를 하나의 표현으로 통일하고 기존 LLM과 연결하는 실용적 파이프라인이 차별점임. 어느 모델을 쓰는지가 아니라 추출한 정보를 어떻게 표현해 LLM에 전달하는지가 제안의 중심임.

근거: 텍스트 LLM은 저수준 SVG 코드(평균 54.9)보다 노드와 관계가 명시된 Graphviz 표현(84.5)에서 그림 질의에 정확함(VGBench, EMNLP 2024). 서로 다른 형식의 평가 결과이므로 기술도면의 그래프 변환이 같은 폭으로 개선된다는 직접 증거는 아니며 본 과제의 실험으로 확인함.

나머지 구성은 이 아이디어를 뒷받침하는 수단임. PDF와 CAD 파싱, OCR은 추출 수단, 이미지 임베딩은 검색 수단, 원본 좌표와 관계 검증은 정확성 수단, 기존 LLM은 활용 수단임.

## 초기 범위

문자, 기호, 연결 관계 복원에 집중함. 치수와 형상의 대응, 차트 계열 복원은 이후 확장임. 사진과 복잡한 렌더링은 이미지 검색에 한정함. 관계 해석 정확도는 그림 유형별로 검증함.

## 효율성

원본 구조 우선 활용. 전처리는 문서 등록 시 1회. 질의 시 관련 부분 그래프만 전달.

## 검증

OCR 기반 RAG와 비교해 관계 질의 정답률, 처리 시간, GPU 사용량 평가. 추출한 관계마다 원본의 어느 영역에 근거하는지 추적함. 정답은 공개 벤치마크(PID2Graph)와 CAD에서 생성한 도면(FreeCAD TechDraw)으로 확보함.
