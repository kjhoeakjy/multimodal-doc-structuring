# v5 모든 기술 그림을 기하 요소 그래프로 변환해 텍스트 LLM이 추론하는 전처리 및 구조화

작성 2026-10-29. v4의 치수와 형상 관계 복원, 설계 원본 기반 정답 생성을 유지하고 적용 대상을 기계도면에서 모든 기술 그림으로 확장한 안. 확장의 수단은 그림 유형과 무관한 공통 표현(기하 요소 그래프)과 그 위에서 동작하는 텍스트 LLM 추론임.

**주제** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**제목** 기하 요소 그래프를 공통 표현으로 하는 기술 그림의 전처리 및 구조화

**핵심 아이디어** 설계도면, 단면도, 회로도, 계통도, 그래프, 기술 삽화는 모두 선, 원호, 문자, 화살표, 닫힌 영역, 기호의 조합임. 모든 그림을 이 기하 요소와 요소 간 관계의 그래프로 변환하고 이를 텍스트로 직렬화해 기존 텍스트 LLM에 전달함. 그림 유형별 해석기는 그래프에 의미(치수, 연결, 계열)를 덧붙이는 역할이며 해석기가 없는 그림도 그래프 자체로 검색과 추론이 가능함. 변환 결과는 그래프가 원본의 요소를 얼마나 설명하는지(설명률)와 기하 제약(길이 일치, 연결 완결)으로 검증함.

**설계 전제** 생성형 시각언어모델(VLM) 미사용. 폐쇄망, 제한된 GPU, 기존 텍스트 LLM. 특정 조직의 시스템과 운영 모델은 전제하지 않음.

## 1. 세 요구 조건과 대응

| 요구 조건 | 대응 | 근거 |
|---|---|---|
| 실제 구현 가능성 | 벡터 원본(PDF, DXF, SVG)은 기하 요소가 이미 존재함. 래스터는 선과 원호 벡터화와 OCR로 변환. 그래프 구성은 규칙과 전역 할당. LLM은 텍스트 입력 | Deep Vectorization of Technical Drawings(ECCV 2020), eDOCr2(Machines 2025), PyMuPDF와 ezdxf |
| 모든 복잡한 그림 | 그림 유형과 무관한 공통 표현. 해석기가 없는 유형도 그래프로 검색, 질의응답, 위치 지정 가능 | 그림은 유형에 관계없이 동일한 기하 요소로 구성됨 |
| 기술적 독창성 | 1. 텍스트 LLM이 이해하는 추상 수준으로 그림을 표현. 2. 그래프의 원본 설명률과 기하 제약으로 해석 결과를 검증. 3. CAD에서 생성한 도면으로 정답을 자동 확보 | VGBench(EMNLP 2024): 텍스트 LLM은 저수준 SVG보다 관계가 명시된 상위 표현에서 정확도가 높음 |

## 2. 문제

### 2.1 그림 이해의 실패 지점

| 근거 | 내용 |
|---|---|
| AECV-Bench(2026) | 멀티모달 모델의 도면 문자 판독 0.7~0.95, 기호 개수 세기 0.40~0.55. 문자를 읽어도 기호와 공간 관계에서 실패 |
| MechVQA(ICML 2026) | 기계도면의 주된 실패는 투영 규칙 아래의 공간 관계 추론. 조립 관계와 다중 뷰 과제가 최저 |
| VGBench(EMNLP 2024) | 텍스트 LLM에 벡터 그래픽 코드를 입력하면 SVG(저수준 경로) 평균 54.9, TikZ 81.0, Graphviz(노드와 연결 명시) 84.5. SVG는 코드가 길수록 정확도 하락 |

세 결과의 공통 해석: 그림 이해의 병목은 화소 인식이 아니라 요소 간 관계의 명시임. 관계가 명시된 표현을 주면 텍스트 LLM도 그림을 추론함. 따라서 전처리의 목표는 그림을 관계가 명시된 그래프로 바꾸는 것임.

### 2.2 기존 접근과의 차이

| 접근 | 한계 |
|---|---|
| OCR과 텍스트 RAG | 문자 외 정보 소실 |
| 이미지 임베딩 | 검색은 가능하나 요소와 관계를 표현하지 못함 |
| 생성형 VLM | 공간 관계 오류, 원본에 없는 값 생성, 좌표 미제공, 폐쇄망 GPU 부담 |
| 유형별 전용 모델(계통도 DTRT, 도면 OCR eDOCr2) | 학습된 유형 외 적용 불가. 유형마다 데이터와 모델 필요 |
| 원시 SVG를 LLM에 입력 | 길이에 따라 정확도 하락(VGBench). 관계가 암묵적 |

## 3. 공통 표현: 기하 요소 그래프

### 3.1 노드

| 노드 | 속성 |
|---|---|
| 선분 | 양 끝 좌표, 선 유형(실선, 파선, 일점쇄선), 굵기 |
| 원호와 원 | 중심, 반지름, 시작각과 끝각 |
| 곡선 | 제어점 |
| 문자 | 내용, 기준 좌표, 방향, 크기 |
| 화살표 | 끝점, 방향 |
| 닫힌 영역 | 경계 요소 목록, 면적, 채움 |
| 기호 | 종류(해석기가 부여), 구성 요소 목록 |

### 3.2 관계

| 관계 | 판정 |
|---|---|
| 접속 | 끝점 간 거리가 허용 오차 이내 |
| 교차 | 두 요소가 중간에서 교차. 접속과 구분 |
| 평행, 수직 | 방향 차이 |
| 포함 | 닫힌 영역 내부 |
| 인접 문자 | 문자와 최근접 요소, 거리와 방향 |
| 지시 | 화살표 끝점이 닿는 요소 |
| 동일 뷰 | 같은 도면 뷰 또는 그림 영역 소속 |

### 3.3 그룹화

연결 성분, 폐곡선, 반복 패턴(동일 형태 요소의 집합)을 상위 노드로 묶음. 그룹화는 LLM 입력 길이를 줄이고 VGBench에서 확인된 상위 표현의 이점을 확보하는 단계임.

### 3.4 직렬화

그래프를 노드 목록과 관계 목록의 텍스트로 변환해 LLM에 전달함. 좌표는 그림 좌표계 기준으로 정규화하고 소수 자릿수를 제한함. 질문과 관련된 부분 그래프에 한정해 전달함.

```
[뷰 A: 정면도]
L1 선분 (0,0)-(120,0) 굵은 실선
L2 선분 (120,0)-(120,40) 굵은 실선
C1 원 중심(60,20) 반지름 5 굵은 실선
D1 치수 "Ø10 ±0.1" 지시 C1 상태 확정
D2 치수 "120" 치수선 (0,-15)-(120,-15) 보조선 L1 양 끝 상태 확정
관계: L1 접속 L2, C1 포함 영역 R1(L1,L2,L3,L4)
```

## 4. 변환 경로

| 원본 | 기하 요소 획득 | 도구 |
|---|---|---|
| DXF, SVG | 요소와 속성이 원본에 존재. 치수 개체는 정의점과 참조 보유 | ezdxf, svgelements |
| 벡터 PDF | 경로와 문자 좌표 추출. 치수 개체는 소실되어 관계 복원 필요 | PyMuPDF |
| 래스터, 스캔 | 전처리(배경 제거, 끊김 보정), 선과 곡선 벡터화, 문자 영역 OCR | Deep Vectorization 계열 또는 OpenCV(선분, 원 검출, 세선화), eDOCr2, Tesseract |
| STEP | 형상과 PMI를 직접 읽어 그래프에 연결 | Open CASCADE Technology |

벡터 원본이 있으면 이미지로 변환하지 않음. 벡터 입력이 래스터 입력보다 정확하다는 결과는 Drawing2CAD(ACM MM 2025)에서도 확인됨(명령 정확도 벡터 80.78%, 래스터 75.60%). 래스터 벡터화는 Deep Vectorization of Technical Drawings(ECCV 2020)가 스캔 도면에서 IoU 79%를 보고함. 벡터화 오차는 설명률(5절)로 드러남.

## 5. 검증

### 5.1 설명률

원본의 기하 요소(벡터) 또는 전경 화소(래스터) 중 그래프의 노드로 설명된 비율. 설명되지 않은 요소는 위치와 함께 미해석 목록에 남김. 설명률은 그림 유형과 무관하게 계산되므로 모든 그림에 적용되는 품질 지표임.

### 5.2 기하 제약

| 대상 | 제약 | 위반 시 |
|---|---|---|
| 치수 | 치수선 길이에 축척을 곱한 값과 표기 값의 일치 | 후보 |
| 치수 | 치수선 하나에 화살표 두 개, 보조선과 형상 연결 | 후보 |
| 연결(계통도, 회로도) | 선의 양 끝이 기호 또는 접점에 접속. 끊어진 선 없음 | 미확정 |
| 영역 | 외형선이 닫힘 | 미확정 |
| 다중 뷰 | 동일 형상의 치수가 뷰 간 일치 | 기각 |
| CAD 대조 | STEP이 있으면 실제 치수와 비교 | 기각 |

해석 결과는 확정, 후보, 기각으로 기록함. 탐지 점수만으로 확정하지 않음. 치수의 길이 일치 검사는 도면이 스스로 정답을 내포하는 성질을 이용하므로 별도 정답 없이 수행됨.

## 6. 그림 유형별 해석기

해석기는 그래프 위에서 동작하는 규칙과 전역 할당이며 그림 유형별로 추가됨. 해석기가 없는 유형은 그래프 자체로 처리됨.

| 유형 | 해석 | 방법 |
|---|---|---|
| 기계도면 | 치수 문자, 치수선, 화살표, 보조선, 형상의 대응 | 거리, 방향, 선 유형 비용의 전역 할당(헝가리안 알고리즘 또는 정수 계획) |
| 계통도, 회로도 | 기호 인식, 선의 연결망 추출, 접점과 교차 구분 | 연결 성분과 접속 관계. 기호는 반복 패턴 그룹의 분류 |
| 그래프, 차트 | 축, 눈금, 범례, 계열 추출. 눈금 기반 좌표 변환으로 수치 복원 | 평행선 집합과 등간격 문자 탐지 |
| 표 | 행, 열, 셀 | TableFormer 또는 선 격자 분석 |
| 단면도, 조립도 | 부품 영역과 해칭, 품번 지시선 | 닫힌 영역과 채움 패턴, 지시 관계 |
| 기타 삽화 | 해석기 없음 | 그래프와 이미지 임베딩으로 검색, 부분 그래프로 질의응답 |

## 7. 검색과 LLM 연결

| 구성 | 내용 |
|---|---|
| 이미지 임베딩 | 페이지와 그림 단위. 경량 멀티모달 임베딩 모델(텍스트와 이미지 구성 10억 매개변수 이하, 오프라인 실행) |
| 그래프 텍스트 검색 | 직렬화된 그래프와 해석 결과의 BM25. 부품번호와 도면번호는 완전 일치 조회 |
| 구조화 데이터 | 노드, 관계, 해석 결과, 검증 상태, 원본 좌표 |
| LLM 입력 | 질문과 관련된 부분 그래프, 확정된 해석, 미해석 목록. 이미지는 입력하지 않음 |
| 응답 | 답변과 근거 요소의 좌표. 미확정 항목은 표시. 설명률이 낮거나 관련 요소가 미해석이면 원본 영역 제시 |

| 질문 | 처리 |
|---|---|
| "이 단면도에서 부품 A와 B가 접하는가" | A, B 영역의 경계 요소 간 접속 관계 조회. CAD가 있으면 OCCT로 확인 |
| "밸브 V-12는 어느 펌프와 연결되는가" | 연결망에서 V-12 노드의 경로 탐색 |
| "구멍의 지름과 공차" | 확정된 치수 조회 |
| "이 그래프에서 80°C일 때의 값" | 계열 좌표 변환 결과 조회 |
| 해석기 없는 그림의 질문 | 부분 그래프를 LLM에 전달해 추론. 답변에 근거 요소 좌표 첨부 |

## 8. 설계 원본 기반 정답 생성

| 단계 | 처리 |
|---|---|
| 1 | STEP 모델(NIST PMI 시험 모델, DeepCAD, 도입 시 조직 보유 CAD) |
| 2 | FreeCAD TechDraw로 투상도와 치수, 단면도, 조립도를 스크립트 생성. 치수와 모서리, 부품과 영역의 대응이 정답으로 남음 |
| 3 | DXF, 벡터 PDF, 래스터(해상도, 번짐, 회전, 압축 변화)로 출력 |
| 4 | 경로별 그래프 변환과 해석 정확도 측정. 검증 허용 오차 조정 |

Drawing2CAD(ACM MM 2025)가 같은 생성 방식으로 15만 건 이상의 도면과 CAD 쌍을 구축함. 계통도와 회로도는 공개 벤치마크(PID2Graph)와 기호 라이브러리 기반 합성으로 보완함. 합성 데이터로 학습한 탐지기는 실제 도면 이전 시 성능이 떨어지고 소량 실제 데이터 보정이 효과적이라는 보고(Tao and Choi, 2026)에 따라 생성 데이터는 평가와 기준 조정에 먼저 쓰고 모델 학습은 한계 확인 후 진행함.

## 9. 실험

| 실험 | 비교 | 판단 질문 | 지표 |
|---|---|---|---|
| 1. 표현 수준 | 원시 SVG 입력 대 기하 요소 그래프 입력(동일 텍스트 LLM) | 그래프 표현이 그림 질의응답 정확도를 높이는가 | 정답률, 입력 토큰 수 |
| 2. 관계 복원 | 최근접 연결 대 전역 할당과 검증 | 치수와 형상, 선과 기호의 관계가 정확해지는가 | 관계 F1, 오확정률 |
| 3. 변환 경로 | 래스터 변환 처리 대 벡터 원본 우선 처리 | 같은 정확도에서 연산량이 줄어드는가 | 쪽당 처리 시간, GPU 시간 |
| 4. 범위 | 해석기 있는 유형 대 없는 유형 | 그래프 자체로 어느 수준까지 답하는가 | 유형별 정답률, 설명률과 정답률의 상관 |

정답은 8절의 생성 데이터, NIST PMI 시험 도면, eDOCr2 공개 예제, PID2Graph, MechVQA(데이터에 한정), ViDoRe V3(검색)로 확보함.

| 대상 | 수준 |
|---|---|
| 모든 그림의 검색과 위치 지정 | 그래프와 이미지 임베딩으로 지원 |
| 해석기 있는 유형의 수치와 관계 질의 | 검증된 결과로 지원 |
| 해석기 없는 유형의 질의 | 부분 그래프 기반 LLM 추론. 정확도는 실험 4로 측정 |
| 사진, 음영 렌더링 | 기하 요소로 분해되지 않음. 이미지 임베딩 검색에 한정 |
| 3D 기하 판단 | CAD가 있을 때 OCCT로 계산. 없으면 범위 밖 |

"모든 그림을 완전히 이해"는 주장하지 않음. 주장하는 것은 모든 그림을 동일한 검증 가능한 표현으로 바꾸고 설명되지 않은 부분을 명시한다는 점임.

## 12. 선행 연구 대비 위치

| 연구 | 내용 | 차이 |
|---|---|---|
| VGBench(EMNLP 2024) | 텍스트 LLM의 벡터 그래픽 이해 평가. 관계 명시 표현에서 높은 정확도 | 이 결과를 전처리 설계 원리로 사용. 그림을 관계 명시 그래프로 변환 |
| SymPoint(ICLR 2024) | 벡터 CAD 도면의 요소를 점으로 보고 기호 인식 | 기호 인식 단계의 참고. 본 구상은 관계 그래프와 검증, LLM 연결 |
| VectorGraphNET(JCCE 2025) | 벡터 PDF 경로 그래프의 선 단위 의미 분할 | 그래프 구성의 선례. 본 구상은 분할이 아니라 관계 복원과 질의응답 |
| eDOCr2(Machines 2025) | 기계도면 치수와 기하공차 OCR | 문자 인식 단계로 사용. 관계 복원과 검증 추가 |
| Drawing2CAD(ACM MM 2025) | CAD에서 도면 생성, 도면에서 CAD 복원 | 같은 생성 방식을 정답 생성과 평가에 사용 |
| DTRT(CVPR 2026) | 계통도 기호와 관계의 학습 기반 추출 | 유형 한정 모델. 본 구상은 공통 표현과 규칙 기반 해석기, 필요 시 모델 추가 |
| TechDocRAG(MDPI AI, 2026) | 문서 조항, 표, 그림의 참조 관계 검색 | 문서 단위. 본 구상은 그림 내부 요소 단위 |

새 학습 알고리즘 개발을 주장하지 않음. 차별점은 세 가지임.

1. **공통 표현**: 모든 기술 그림을 텍스트 LLM이 추론 가능한 추상 수준의 기하 요소 그래프로 변환함
2. **검증**: 설명률과 기하 제약으로 해석 결과를 확정, 후보, 기각으로 판정하고 미해석 부분을 명시함
3. **정답 생성**: CAD에서 도면을 생성해 사람 라벨 없이 변환과 해석의 정확도를 측정함
