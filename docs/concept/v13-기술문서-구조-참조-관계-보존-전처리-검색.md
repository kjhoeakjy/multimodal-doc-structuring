# v13 항공기 기술문서의 구조와 참조 관계 보존을 위한 비정형 데이터 전처리 및 검색 연계

작성 2026-10-29. v12까지의 구상과 별개로 처음부터 다시 작성한 안.

**주제** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**제목** 항공기 기술문서의 구조와 참조 관계 보존을 위한 비정형 데이터 전처리 및 검색 연계 시스템

**핵심 아이디어** PDF, 표, 도면, CAD에 포함된 기술정보를 구조화하고 부품, 규격, 문서 사이의 관계를 보존해 기존 텍스트 LLM이 정확하게 활용하도록 함. 새 LLM 개발이 아니라 LLM에 전달되는 데이터의 품질과 검색 방식 개선이 목적임.

**설계 전제** 외부 API 없는 폐쇄망. 제한된 GPU. 기존 텍스트 LLM 활용. 특정 조직의 시스템과 운영 모델은 전제하지 않음.

## 1. 설계 원칙

| 원칙 | 내용 |
|---|---|
| 원본 우선 추출 | PDF와 CAD에 존재하는 텍스트와 속성은 직접 추출. OCR과 비전 모델은 필요한 영역에 한정 |
| 문서 구조 보존 | 표의 행과 열, 조항 계층, 부품 관계, 참조 문서, 개정 정보 유지 |
| 구조화 데이터와 검색의 결합 | 수치와 식별자는 데이터베이스 조회. 자연어 설명은 LLM |
| 대형 VLM 비의존 | OCR, 경량 레이아웃 및 표 인식 모델, 규칙 기반 처리의 조합 |
| 자원 분리 | 전처리는 사전에 CPU 중심 수행. GPU는 LLM 응답 생성에 할당 |
| 폐쇄망 운용 | 내부 서버 실행. 엣지에서는 일부 모듈 선택 운용 |

## 2. 문제 정의

일반적인 검색 증강 생성(RAG)은 원문을 텍스트로 추출하고 고정 길이로 분할해 유사한 조각을 검색함. 항공기 기술문서에서는 다음 손실이 발생함.

| 손실 | 사례 | 결과 |
|---|---|---|
| 표 구조 | 부품번호, 재질, 체결 토크의 대응 관계 단절 | 다른 부품의 규격 답변 |
| 문서 계층 | 적용 조건과 세부 규격이 별도 조각으로 분리 | 적용 조건 누락 |
| 도면 참조 | 도면번호, 부품번호, 주석의 연결 누락 | 무관한 정보 검색 |
| CAD 정보 | 조립 계층과 부품 속성이 일반 문자열로 변환 | 상위 조립체와 하위 부품 혼동 |
| 개정과 적용 범위 | 다른 개정판이나 형식의 문서 혼재 | 적용할 수 없는 기준 답변 |
| 입력 비효율 | 긴 원문과 불필요한 조각 전달 | 토큰과 지연 시간 증가 |

문제의 본질은 OCR 정확도가 아님. 정보를 정확히 추출하더라도 그 정보가 어느 부품과 문서에 속하는지 잃으면 답변이 틀림. TechDocRAG(AI, MDPI, 2026)도 기술문서의 조항, 표, 그림, 절차 사이 참조 관계 보존이 검색과 근거 추적에 결정적임을 보였음.

### 대표 업무 사례

모든 부품번호와 수치는 설명을 위한 가상 예시임.

**질문** "부품 P-102의 체결 토크와 적용 조건"

| 근거 위치 | 내용 |
|---|---|
| 부품 명세표 | 체결 토크 8 N·m |
| 기술 규격서 4.2절 | 윤활 상태 및 체결 조건 |
| 도면 메타데이터 | 부품 P-102, 도면 D-021 |
| 문서 적용 정보 | 승인된 개정판 C, 적용 제품 범위 |

**목표 응답** 수치와 함께 적용 조건, 근거 문서, 개정 정보 제시. 단일 PDF 요약이 아니라 서로 다른 형식으로 저장된 근거를 찾아 연결하는 문제임.

## 3. 전체 구조

등록 시점 처리와 질의 시점 처리를 분리함.

| 계층 | 시점 | 처리 | 자원 |
|---|---|---|---|
| 1. 문서 파싱 | 등록, 변경 | 디지털 PDF 직접 추출. 스캔 영역 OCR과 레이아웃, 표 인식. STEP의 조립 계층과 제품 제조 정보(PMI) 추출 | CPU 중심 |
| 2. 구조화 | 등록, 변경 | 식별자 정규화, 단위 검증, 표 관계 복원, 문서와 부품 참조 연결, 개정 정보 관리. 공통 스키마와 근거 관계 테이블 생성 | CPU |
| 3. 혼합 검색 | 질의 | 권한과 적용 범위 필터, 식별자 조회, BM25, 임베딩 검색, 순위 결합, 관계 확장 | CPU |
| 4. 기존 텍스트 LLM | 질의 | 검증된 근거로 답변 생성. 문서 번호, 개정판, 쪽, 표 번호 제시 | GPU |

계층별 독립 개선이 가능함. LLM 교체나 GPU 증설 시 전처리 파이프라인 재개발이 불필요함.

## 4. 계층 1: 문서 유형별 전처리

원본의 구조화 정도에 따라 처리 경로를 선택함.

| 입력 | 우선 처리 | 추가 처리 |
|---|---|---|
| 텍스트 층이 있는 PDF | 텍스트와 좌표 직접 추출 | 표 구조 분석 |
| 스캔 PDF | OCR | 레이아웃과 표 인식 |
| DOCX, XLSX | 원본 XML과 셀 구조 파싱 | 없음 |
| 2D 도면 PDF | 텍스트, 도형, 주석 좌표 추출 | 특정 영역 OCR |
| STEP | 제품 계층, 속성, PMI 직접 추출 | 미지원 속성 별도 처리 |
| S1000D 등 XML 문서 | 스키마 기반 파싱 | 없음 |

S1000D는 항공과 방산 분야의 기술 간행물 국제 표준으로 문서 식별, 적용 대상(applicability), 상태 정보를 정의함. 메타데이터 설계의 참고 표준으로 활용함.

### 4.1 PDF

| 단계 | 처리 | 근거 |
|---|---|---|
| 1. 직접 추출 | PyMuPDF 또는 pdfium으로 텍스트와 좌표 추출 | 텍스트가 있는 문서를 이미지로 바꿔 OCR을 다시 적용하면 오류가 추가됨 |
| 2. 레이아웃 분석 | 다단, 제목과 본문, 표와 캡션이 복잡한 쪽에 Docling 표준 PDF 파이프라인의 레이아웃 모델 적용 | Docling(AAAI 2025) |
| 3. 선택적 OCR | 텍스트 층이 없는 영역에 Tesseract 적용 | OCR 오류는 검색과 생성으로 전파됨(OCR Hinders RAG, ICCV 2025) |

### 4.2 표 구조 복원

TableFormer(CVPR 2022) 또는 Table Transformer(PubTables-1M, CVPR 2022)로 행, 열, 셀 구조를 복원함. PubTables-1M은 약 95만 개 표로 표 탐지와 구조 인식을 학습한 데이터셋임. Docling의 TableFormer는 빠른 모드와 정밀 모드를 제공해 표 복잡도에 따라 비용 조절이 가능함.

| 원본 규격표(가상) | | |
|---|---|---|
| Part ID | Material | Torque |
| P-101 | AL6061 | 12 N·m |
| P-102 | SUS304 | 8 N·m |

복원 결과는 행 단위 레코드로 저장함. P-101: 재질 AL6061, 체결 토크 12 N·m. P-102: 재질 SUS304, 체결 토크 8 N·m.

행과 열 탐지 외 처리 항목:

- 병합 셀 머리글의 하위 셀 연결
- 머리글에 표기된 단위의 개별 값 적용
- 여러 쪽에 걸친 표의 머리글 유지
- 표와 각주의 적용 조건 연결
- 원본 쪽과 셀 위치 저장

표 전체를 하나의 마크다운 조각으로 만들지 않고 속성을 개별 레코드로 추출하며 원본 표 구조를 함께 보관함.

### 4.3 도면과 CAD

| 대상 | 추출 항목 | 수단 |
|---|---|---|
| 2D 도면 PDF | 도면번호, 표제란, 개정판, 부품번호, 주석, 치수 표기와 좌표 | 직접 추출. 필요 시 영역 OCR |
| STEP(AP242) | 제품명, 조립 계층, 부품 속성, 치수와 공차(PMI) | Open CASCADE Technology의 STEP 처리 기능. 참고 도구 NIST STEP File Analyzer |

CAD 원본에 속성이 존재하는 경우와 2D 도면 이미지에서 속성을 추론하는 경우는 별개의 문제임. 초기 범위는 CAD 원본 속성과 2D 도면의 표제란, 주석, 규격 정보 추출로 한정하고 복잡한 기하 관계의 자동 해석은 제외함.

## 5. 계층 2: 기술정보 구조화

전체 제안의 핵심 단계임. 텍스트 추출 품질만으로는 차별성이 없음. 추출된 정보의 의미와 연결 대상을 보존하는 데이터 구조가 필요함.

### 5.1 공통 스키마

| 개체 | 주요 속성 |
|---|---|
| 문서 | 문서번호, 제목, 개정판, 승인 상태, 접근 권한 |
| 부품 | 부품번호, 명칭, 재질, 상위 조립체 |
| 규격 | 속성명, 값, 단위, 적용 조건 |
| 조항 | 절 번호, 내용, 상위 절 |
| 표 | 표 번호, 행과 열, 머리글 구조 |
| 도면 | 도면번호, 관련 부품, 원본 위치 |
| 근거 | 추출 출처, 좌표, 추출 방식, 검증 상태 |

규격과 근거를 분리함. "체결 토크 12 N·m"는 규격이고 "SPEC-001 개정판 C 표 3에서 확인"은 근거임. 두 정보를 함께 저장하면 오류 발생 시 원인 단계 확인이 가능함.

### 5.2 근거 관계 테이블

초기에는 그래프 데이터베이스 없이 SQLite의 노드 테이블과 관계 테이블로 구현함.

| 관계 | 의미 |
|---|---|
| contains | 문서가 조항이나 표를 포함 |
| has_specification | 부품에 적용되는 규격 |
| references | 다른 문서나 도면 참조 |
| part_of | 부품이 조립체에 포함 |
| supersedes | 이전 개정판 대체 |
| applies_to | 적용 가능한 제품, 형식, 구성 |

관계는 LLM이 생성하지 않음. 문서 식별자, 참조번호, CAD 계층 등 원문에 명시된 정보로 생성하고 확인되지 않은 관계는 확정하지 않음. 이름 유사성에 의한 자동 연결은 금지함.

### 5.3 식별자와 단위 정규화

P-101, P101, P 101은 동일 부품일 수도 있고 규칙에 따라 다른 부품일 수도 있음. 처리 순서는 원본 식별자 보존, 형식 검사, 허용 별칭 생성, 기준 식별자 대응, 충돌 검사임. 원본 값은 삭제하지 않고 식별자 종류별 규칙을 적용함.

값과 단위는 분리 저장함(12, N·m). 단위 변환은 Pint 등 단위 라이브러리로 수행하고 단위나 적용 조건이 불명확한 값은 변환하지 않음.

### 5.4 개정과 적용 범위

최신 개정판 검색으로는 부족함. 제품 형식, 구성, 유효 일련번호 범위에 따라 다른 규격이 적용됨. 검색 단위마다 문서번호, 개정판, 승인 상태, 적용 범위를 함께 저장함. 적용 조건이 불명확하면 하나를 임의 선택하지 않고 추가 조건을 요청하거나 적용 가능한 후보를 함께 제시함.

## 6. 계층 3: 구조 기반 혼합 검색

벡터 검색만으로는 부품번호와 정확한 규격 검색이 어려움. 식별자 조회, BM25, 임베딩 검색, 관계 확장을 조합함.

### 6.1 검색 절차

| 단계 | 처리 | 예시("P-101의 체결 조건") |
|---|---|---|
| 1. 질의 분석 | 식별자와 질의 유형 추출 | 부품 P-101, 규격 조회 |
| 2. 필터 | 접근 권한, 승인 상태, 적용 범위 확인 | 승인된 개정판, 해당 형식 |
| 3. 검색 | 식별자 조회(SQL), BM25, 임베딩 검색 병행 | |
| 4. 결합과 확장 | 상호 순위 융합(RRF) 후 상위 절, 참조 표, 적용 조건 연결 | 4.2절 체결 조건 추가 |
| 5. 전달 | 근거 묶음을 LLM에 전달 | 값, 조건, 출처 |

### 6.2 도구

| 기능 | 도구 | 선택 이유 |
|---|---|---|
| 정확한 값 조회 | SQLite, PostgreSQL | 부품번호와 속성 조회 |
| 키워드 검색 | SQLite FTS5(BM25) | 규격번호와 기술 용어 검색. 한국어는 trigram 토크나이저 또는 형태소 분석 적용 |
| 의미 검색 | multilingual-e5-small | 약 1억 1,800만 매개변수, 384차원. 한국어와 영어 검색 |
| 벡터 검색 | FAISS(CPU) | GPU 없이 검색 |
| 순위 결합 | RRF(SIGIR 2009) | 순위만으로 결합. 별도 재순위 모델 불필요 |
| 관계 확장 | SQL 조인 | 참조 조항과 적용 조건 연결 |
| 응답 생성 | 기존 텍스트 LLM | 근거의 자연어 설명 |

### 6.3 질의 유형별 처리

| 질의 | 우선 처리 |
|---|---|
| "P-101의 재질" | 부품번호 직접 조회 |
| "SPEC-001 4.2절 내용" | 문서번호와 절 번호 검색 |
| "이 부품의 적용 조건" | 식별자 조회와 관계 확장 |
| "특정 재질의 체결 기준" | BM25와 임베딩 검색 |
| "두 개정판의 차이" | 개정판별 구조화 데이터 비교 |

초기에는 정규표현식과 식별자 사전으로 분류함. 복잡한 질의에 한해 LLM 기반 질의 분석을 추가함.

### 6.4 구조 기반 분할

고정 길이(512~1,024토큰) 분할을 기본값으로 쓰지 않음.

| 문서 유형 | 검색 단위 |
|---|---|
| 일반 문단 | 조항 |
| 절차 문서 | 절차 단계 |
| 규격표 | 행 또는 논리적으로 연결된 셀 |
| 부품 명세 | 부품번호와 속성 |
| CAD | 부품, 조립체와 속성 |

각 단위에 상위 문서 제목, 문서번호, 개정판을 부착함. 검색은 작은 단위로 수행하고 LLM 입력에는 적용 조건과 출처를 함께 제공함.

## 7. 계층 4: 기존 텍스트 LLM 연결

| LLM 담당 | LLM 비담당 |
|---|---|
| 질문 이해와 검색 요청 구성 | 근거 없는 규격 수치 생성 |
| 검색된 표와 문서의 자연어 설명 | 부품 간 관계 추측 |
| 여러 근거의 연결 요약 | 적용 범위 임의 선택 |
| 원문 확인용 출처 제시 | 미승인 문서 사용, 설계와 제조 조건 확정 |

조회된 수치(P-101 체결 토크 12 N·m)는 SQL 결과를 그대로 전달하고 LLM은 의미와 조건을 설명함. 생성 후 숫자, 단위, 부품 식별자가 근거와 일치하는지 규칙 기반으로 검증함. 정보의 원천은 검증된 기술문서이고 LLM은 설명 계층임.

## 8. 대형 VLM 비의존의 근거

| 작업 | 대형 VLM 필요 여부 | 구현 |
|---|---|---|
| 디지털 PDF 텍스트 추출 | 불필요 | PDF 파서 |
| 스캔 문서 문자 인식 | 불필요 | OCR |
| 문서 영역 분류 | 불필요 | 경량 객체 탐지 모델 |
| 표 행과 열 복원 | 불필요 | TableFormer |
| CAD 제품 계층 추출 | 불필요 | STEP 파서 |
| 부품번호와 속성 연결 | 불필요 | 규칙과 SQL |
| 한국어와 영어 검색 | 불필요 | 텍스트 임베딩 |
| 복잡한 도면의 시각적 의미 추론 | 경우에 따라 필요 | 별도 비전 분석 또는 전문가 확인 |

OCR과 TableFormer도 비전 모델임. 비전 모델 배제가 아니라 대형 생성형 VLM 없이 필요한 시각 정보를 추출하는 구성임. 원본에 구조화된 정보가 없고 이미지의 기하 관계를 새로 추론해야 하는 경우는 제안 시스템의 범위 밖임. 이 경우 답변을 생성하지 않고 원본 도면을 함께 제시하거나 전문가 검토 대상으로 분류함.

## 9. GPU 효율성

핵심은 모델 경량화보다 불필요한 모델 실행의 축소임.

### 9.1 단계별 자원

| 구성 요소 | 자원 | 실행 시점 |
|---|---|---|
| PDF 직접 추출 | CPU | 등록, 변경 |
| OCR | CPU | 스캔 영역 존재 시 |
| 레이아웃과 표 구조 분석 | CPU 우선 | 등록, 변경 |
| CAD 속성 추출 | CPU | CAD 변경 시 |
| 검증과 구조화 | CPU | 등록, 변경 |
| 임베딩 생성 | CPU 우선 | 색인 생성, 질의 |
| BM25, FAISS 검색 | CPU | 질의 |
| LLM 응답 생성 | GPU | 질의 |

Docling은 CPU 추론과 오프라인 실행을 지원하며 모델 가중치를 사전 반입해 내부 배포할 수 있음. CPU 처리 시간은 실측 대상이며 CPU가 빠르다는 주장은 하지 않음.

### 9.2 최적화 방안

| 방안 | 내용 |
|---|---|
| 선택적 OCR | 텍스트 층이 없는 영역에 한정 |
| 모델 미사용 우선 | 단순 PDF는 직접 추출 |
| 증분 색인 | 문서 해시와 개정판 확인 후 변경 문서 재처리 |
| 질의 기반 입력 축소 | 질문에 필요한 표와 조항 전달 |
| 임베딩 캐시 | 중복 문장과 미변경 문서의 임베딩 재사용 |
| LLM 미호출 응답 | SQL로 답할 수 있는 단순 조회는 구조화 결과를 직접 반환 |

위 방안은 LLM 입력 토큰과 호출량을 줄이는 수단이며 LLM 서버의 동시 접속 처리를 직접 해결하는 기술은 아님.

### 12.3 개정과 적용 조건 시험

동일 부품번호에 대해 제품 형식이나 개정판을 다르게 설정한 질문을 구성하고 적용할 수 없는 규격의 반환 여부를 측정함. 일반 RAG 정확도 평가보다 항공기 기술정보 활용 목적에 가까운 시험임.

### 12.4 데이터

| 데이터 | 용도 |
|---|---|
| NIST PMI 시험용 CAD 모델(STEP AP242) | 부품과 속성 추출 검증 |
| 공개 기술 매뉴얼(FAA AC 43.13-1B 등) | PDF와 표 처리 검증 |
| DesignQA(규정 문서, CAD 이미지, 도면 질의응답) | 기술문서 질의응답 공개 기준 |

공개 데이터의 결과를 실제 항공기 제조 문서로 일반화하려면 추가 검증이 필요함.

## 14. 선행 연구 대비 위치

가장 가까운 선행 연구는 TechDocRAG(Lee and Choi, AI 7(5):161, MDPI, 2026)임. 문서를 조항, 표, 그림, 캡션, 절차 단계의 이종 그래프로 파싱하고 식별자 기반 회수, 질의 의도별 그래프 확장, 원문 근거 묶음 전달을 수행함. 보존 관계에 참조(clause_ref, table_ref, figure_ref), 동일 식별자, 개정(version_of, supersedes)을 포함함. 4개 공개 기준(MPMQA, DesignQA, MMLongBench-Doc, LongDocURL)에서 BM25와 밀집 검색의 혼합 기준선 대비 평균 20.3점 향상을 보고함. 생성 모델은 외부 상용 모델(Gemini)임.

| 항목 | TechDocRAG | 본 구상 |
|---|---|---|
| 관계 보존 검색 | 이종 그래프, 식별자 회수, 관계 확장 | 차용. SQL 관계 테이블로 경량 구현 |
| 수치 전달 | 원문 근거 묶음을 생성 모델에 전달 | 규격과 근거 분리 저장. 조회 수치는 SQL 결과 그대로 전달하고 생성 후 수치, 단위, 식별자 대조 |
| 개정과 적용 범위 | 개정 관계 보존, 일관성 지표(VCS) | 검색 전 필터로 적용. 불명확 시 조건 요청 또는 후보 제시 |
| 입력 범위 | PDF 문서 | PDF와 STEP 원본 속성(조립 계층, PMI) 직접 추출 |
| 실행 환경 | 외부 생성 모델 | 폐쇄망, CPU 전처리, 기존 텍스트 LLM |

새 학습 알고리즘 개발을 주장하지 않음. 선행 기술을 항공기 기술문서의 데이터 환경에 맞춰 선택, 결합, 검증하는 응용 시스템 설계임.

### 기술적 차별점

1. **원본 우선 선택적 파싱**: 원본 특성에 따라 직접 추출, OCR, 표 구조 인식 중 처리 경로 결정
2. **근거 보존 구조화**: 수치와 기술정보를 부품, 문서, 개정 정보, 원본 위치까지 연결해 저장
3. **혼합 근거 검색**: 식별자 조회와 의미 검색을 결합하고 관련 조항과 적용 조건을 함께 찾아 기존 텍스트 LLM에 전달

대형 VLM이나 LLM 학습 없이 기술문서에 대한 AI 활용성을 개선하는 구현 가능한 구성임. 처리를 단일 모델에 맡기지 않아 CPU와 GPU 자원을 분리 관리할 수 있고 폐쇄망에서 모듈 단위 운영에 적합함.
