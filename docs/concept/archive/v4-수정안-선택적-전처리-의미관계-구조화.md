# v4 수정안: 비정형 데이터의 선택적 전처리 및 의미·관계 보존형 구조화 (현행)

작성 2026-10-28. v4 초안을 수정함. 방향 확정.

**주제:** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**설계 전제:** 외부 API 없이 공개 가중치 모델을 내부 환경에서 실행할 수 있고 GPU 자원이 제한된 상황을 가정함. 특정 기업의 실제 시스템 구성을 전제하지 않음.

## 0. v4 초안 대비 변경

| v4 초안 | 수정 | 사유 |
|---|---|---|
| 데이터별 파서·OCR·VLM 선택 | 원본 직접 파싱 + 소형 통합 문서 VLM | 모델 종류와 처리 과정 단순화 |
| 표·도면·사진을 각각 정형 데이터로 변환 | 구조화 가능한 정보 추출 + 원본 시각 정보 보존 | 모든 이미지의 의미를 완전히 구조화할 수는 없음 |
| 재구성 대조 검증 | 형식·관계·원본 근거 검증 + 불확실 영역 재처리 | 재구성 결과만으로 추출 정확성 보장 불가 |
| 모든 셀에 자기완결 정보 저장 | 계층적 저장, 질의 시 맥락 복원 | 메타데이터 중복 감소 |
| 조회용 DB·검색용 서술문·원본 영역 | 유지, 질문별 Evidence Packet 추가 | 로컬 LLM에 필요한 정보만 제공 |
| 질의 시 이미지 입력 제거 | 구조화 정보 우선, 필요 시 원본 영역 사용 | 시각 정보 손실 방지 |

핵심 변경은 전처리 단순화(통합 문서 모델)와 질문별 Evidence Packet 구성임.

## 1. 핵심 문제 정의

표·이미지·기술문서는 단순 텍스트 변환 과정에서 행·열, 객체·주석, 적용 조건 등 중요한 관계가 손실될 수 있음. 반대로 모든 원본을 멀티모달 LLM에 직접 입력하면 이미지 처리 연산과 입력 문맥이 증가함.

따라서 원본 정보의 의미와 관계를 보존하면서 AI가 필요한 정보만 효율적으로 사용할 수 있도록 하는 전처리·구조화 체계가 필요함.

## 2. 핵심 해결 전략

**축 1. 데이터 전처리: 선택적·단계적 정보 추출**
원본 파일에서 정보를 직접 추출할 수 있는지 먼저 확인하고, 이미지 기반 처리가 필요한 경우에 경량 통합 문서 이해 모델을 사용함. 추출 결과를 검증한 뒤 불확실한 영역만 추가 분석함.

**축 2. 데이터 구조화: 의미·관계·근거 보존**
추출 결과를 대상, 속성, 값, 단위, 적용 조건, 원본 근거로 구조화함. 저장 단계에서는 계층과 참조 관계를 유지하고 질의 시점에는 필요한 맥락만 조립해 LLM에 제공함.

두 축을 연결하는 설계 원칙: 정보 손실을 최소화하면서 반복적인 이미지 처리와 불필요한 입력 토큰을 줄임.

## 3. 축 1: 데이터 전처리

### 3.1 입력 특성에 따른 처리 경로

| 입력 유형 | 기본 처리 | 추가 처리 조건 |
|---|---|---|
| 디지털 문서·전자 표 | 원본 파서로 텍스트, 셀, 메타데이터 추출 | 표 구조 또는 읽기 순서 불명확 |
| 스캔 문서·표 이미지 | 소형 통합 문서 VLM으로 레이아웃·텍스트·표 구조 추출 | 수치 누락, 병합 셀 오류, 원본과 불일치 |
| 다이어그램·일반 이미지 | 객체, 문자, 주석 및 영역별 정보 추출 | 시각적 의미나 객체 간 관계의 추가 판단 필요 |
| 혼합형 문서 | 직접 파싱과 이미지 추출 결과 결합 | 동일 영역의 추출 결과 상충 |

문서 VLM은 텍스트·표·차트·레이아웃 추출을 통합 처리하되 일반 사진이나 복잡한 도식의 의미 해석까지 항상 보장한다고 가정하지 않음.

### 3.2 추출 단계

1. **원본 분석 및 직접 파싱:** 파일 형식, 텍스트 레이어, 표 구조, 페이지·영역 정보 확인. 직접 추출 가능한 데이터는 GPU 기반 이미지 모델을 거치지 않음.
2. **통합 문서 VLM:** 직접 파싱이 어려운 페이지·영역에 경량 문서 이해 모델 적용. 산출물은 텍스트, 제목·문단 계층, 표 행·열, 수식, 이미지 설명, 영역 유형, 위치 좌표, 읽기 순서.
3. **정규화:** 숫자와 단위 분리, 자료형 지정, 원문 식별자·용어 보존. 단위 환산·용어 통합은 검증 가능한 규칙이 있을 때 수행.
4. **불확실 영역 추가 처리:** 불완전하거나 모순되는 영역에 한해 고해상도 재분석, 다른 추출 방법 또는 사람 확인 적용.

### 3.3 검증 전략

재구성 대조는 보조 수단. 추출 정확성 판단은 아래 세 가지로 수행함.

| 검증 | 확인 사항 |
|---|---|
| 형식 검증 | 필수 필드, 자료형, 단위, 표 구조, 좌표 유효성 |
| 관계 검증 | 표 헤더와 셀, 이미지 주석과 객체, 조건과 값의 연결 |
| 원본 근거 검증 | 추출값과 원본 셀·문구·이미지 영역의 대응 |

검증되지 않은 정보는 확정값과 분리해 관리함. 원본 대조만으로 판정할 수 없는 내용은 미확정 상태 유지.

### 3.4 전처리 산출물

원본 문서를 구조화된 문서 요소로 변환함.
- 요소 유형: 제목, 문단, 표, 셀, 이미지, 주석
- 내용: 추출 텍스트·수치, 단위, 구조 정보
- 위치: 문서 ID, 페이지, Bounding Box, 셀 위치
- 상태: 검증 결과, 추가 확인 필요 여부

원본 파일과 시각적 영역은 별도 보존.

## 4. 축 2: 데이터 구조화

### 4.1 공통 스키마

| 필드 | 의미 |
|---|---|
| Subject | 정보가 설명하는 대상 |
| Attribute / Relation | 대상의 속성 또는 다른 대상과의 관계 |
| Value / Unit | 값과 단위 |
| Qualifier | 적용 조건, 범위, 예외 |
| Parent Context | 문서·절·표·행·이미지 계층 |
| Provenance | 원본 문서, 버전, 페이지, 셀·이미지 좌표 |
| Validation Status | 확인·불확실·검토 필요 |

표 헤더나 공통 적용 조건처럼 반복되는 정보는 상위 구조에 저장하고 개별 정보는 참조 관계로 연결함. 저장 중복을 줄이면서 필요한 문맥 복원 가능.

### 4.2 정보 간 관계 보존

서로 다른 형식에서 추출한 정보가 동일 대상을 가리키는 경우 연결함. 예: 이미지의 대상 A-17, 표의 A-17 허용 온도, 문서의 적용 조건을 관계 확인 후 하나의 정보 집합으로 구성.

동일 식별자 출현만으로 연결을 확정하지 않음. 대상 범위, 적용 조건, 버전의 일치 여부 확인.

### 4.3 저장 구조와 LLM 입력 구조 분리

- **저장용:** 관계형 테이블 또는 구조화 문서 객체에 전체 정보와 원본 참조 보존. 조회용 구조와 검색 인덱스 분리 가능.
- **검색용:** 정보 단위의 대상, 속성, 적용 조건, 상위 제목을 검색 가능한 형태로 구성. 키워드 검색 기본, 필요 시 소형 임베딩 검색 결합.
- **LLM 입력용:** 질문에 필요한 정보만 검색한 뒤 상위 문맥과 출처를 복원해 간결한 Evidence Packet으로 구성.

### 4.4 질문별 최소 충분 근거 구성

| 질문 유형 | 필요한 정보 | 활용 방식 |
|---|---|---|
| 단일 값 조회 | 대상·속성·값·조건 | 정형 DB 직접 조회 |
| 여러 값 비교 | 비교 대상별 값·단위·적용 조건 | DB 조회 및 규칙 기반 비교 |
| 기술적 설명 | 관련 정보 단위·문서 조항·출처 | LLM에 근거 전달 |
| 시각적 판단 | 구조화 정보와 원본 이미지 영역 | 필요 시 멀티모달 모델 |

질문에 필요한 대상·조건·근거가 확보됐는지 확인함. 충분하면 입력 확정, 부족하면 추가 검색 또는 원본 영역 확인, 근거 미확보 시 답변 보류. 토큰 감소 자체가 목적이 아니며 정확한 답변에 필요한 근거를 보존하는 범위에서 입력을 줄임.

## 5. 폐쇄망 및 제한된 연산 자원 대응

- **실행 시점 분리:** 문서 등록·변경 시 구조화 결과 생성·저장. 질의 시 기존 결과 조회로 동일 페이지 이미지 해석 반복 제거. GPU 사용량이 높은 전처리는 서비스 추론과 경쟁하지 않도록 별도 작업 대기열·자원 예산으로 관리.
- **경량 모델:** 전처리에 소형 VLM 우선 적용. 하드웨어·모델·런타임이 지원하면 양자화를 검토하되 추출 정확도와 메모리·속도를 비교해 채택 결정. 검증 실패 영역만 추가 추론 또는 사람 검토.
- **질의 입력 최소화:** 구조화 데이터에서 값 직접 조회, LLM 추론이 필요한 경우에만 근거 제공. 반복 이미지 처리, 불필요한 문맥, 긴 프롬프트의 추가 메모리 사용 감소 가능성.
- **폐쇄망 실행:** 모델 가중치·토크나이저·라이브러리를 승인 절차로 사전 확보해 내부 실행. 외부 API를 필수 구성 요소로 사용하지 않음. 라이선스, 실행 환경 호환성, 원본 데이터 접근 권한 확인.

## 6. 차별화 요소

1. **통합 모델 기반 전처리 단순화:** 텍스트·표·차트·레이아웃을 하나의 경량 문서 이해 모델로 처리하는 범위를 넓히고 원본 파싱과 예외 영역 분석을 결합.
2. **검증 가능한 의미·관계 보존:** Markdown 변환에서 끝내지 않고 대상·값·조건·원본 근거를 연결해 잘못된 문맥 해석 감소.
3. **질문별 최소 충분 근거 구성:** 저장 데이터를 전부 입력하지 않고 필요한 정보와 관계를 검색해 LLM 입력 구성. 부족한 근거는 추가 확보, 불확실한 내용은 미확정.

개별 기술은 기존 연구에 기반함. 제안의 차별점은 정확도와 연산 효율을 함께 고려한 전처리·구조화·입력 구성의 연계 설계.

## 7. PoC 및 성능 검증

### 7.1 비교 실험

| 실험군 | 전처리 | 구조화 및 LLM 입력 |
|---|---|---|
| A. 기본 | OCR | 고정 길이 텍스트 청크 |
| B. 통합 모델 | 모든 문서 이미지에 문서 VLM | Markdown 청크 |
| C. 구조화 | 문서 VLM | 의미·관계 구조화 + Evidence Packet |
| D. 최종 제안 | 직접 파싱 + 선택적 문서 VLM + 검증 | 의미·관계 구조화 + Evidence Packet |

A~D에 동일 LLM, 동일 질의 데이터, 동일 하드웨어 적용. B·C 차이로 구조화 효과, C·D 차이로 전처리 경로 최적화 효과 분석.

### 7.2 지표

| 분류 | 지표 |
|---|---|
| 전처리 정확성 | 텍스트·수치 추출 정확도, 표 구조 F1 |
| 구조화 정확성 | 객체·속성·조건 연결 정확도, 출처 일치율 |
| AI 활용 성능 | QA 정확도, 근거 충실도, 답변 보류 적절성 |
| 연산 효율 | 문서당 전처리 시간, GPU 사용량, 질의당 입력 토큰 수 |
| 운영 비용 | 재사용 횟수를 고려한 질의당 총 처리 비용 |

구조화로 정확도가 낮아지는 경우도 기록함. 입력 토큰 감소만으로 개선을 주장하지 않음.

### 7.3 Before/After 사례

동일 표·이미지·문서에서 기본 방식은 적용 조건을 놓쳐 잘못된 답을 생성하고 제안 방식은 조건을 보존해 올바른 근거를 선택하는 사례 1건과 두 방식의 입력 토큰 실측을 1장에 포함함.

유의: 모델 통합이 연산 비용 감소를 보장하지 않음. 디지털 PDF까지 이미지로 렌더링해 처리하면 CPU 파서보다 비효율적일 수 있으므로 선택적 전처리 구조가 필요함.

## 9. 1장 구성(안)

제목: 비정형 데이터의 의미 보존과 효율적인 AI 활용을 위한 전처리·구조화 전략

- 문제: 구조 손실, 반복 이미지 처리, 불필요한 입력 문맥
- ① 데이터 전처리: 원본 직접 파싱, 경량 통합 문서 모델, 불확실 영역 검증·재처리
- ② 데이터 구조화: 대상·값·조건·근거 연결, 문서 계층·관계 유지, 질의별 최소 충분 근거 구성
- AI 활용: 정형 정보 직접 조회, 필요한 근거만 로컬 LLM 전달, 원본 이미지 선택적 활용
- 검증: 추출·관계 정확도, QA 정답률, 입력 토큰·GPU 연산 비용
- Before/After 사례 1건

모델 경량화·양자화·GPU 스케줄링은 별도 축으로 두지 않음. 공개된 일반 기술문서·표·이미지 예시만 사용.
