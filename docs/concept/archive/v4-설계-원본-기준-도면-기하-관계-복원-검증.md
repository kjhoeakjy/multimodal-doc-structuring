# v4 설계 원본을 기준으로 한 기술도면의 기하 관계 복원과 검증

작성 2026-10-29. v3의 구성 요소를 줄이고 도면 정보의 기하 관계 복원과 검증, 설계 원본을 이용한 정답 자동 생성을 중심 기술로 재편한 안.

**주제** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**제목** 설계 원본 기반 기하 관계 복원과 검증을 통한 기술도면 전처리 및 구조화

**핵심 아이디어** 기술도면의 치수, 공차, 부품 참조를 문자로 읽는 데 그치지 않고 그 값이 어느 형상을 가리키는지 기하 관계로 복원하고 검증함. 제조 조직이 보유한 CAD와 벡터 원본을 정답으로 사용해 사람의 라벨링 없이 추출 정확도를 측정하고 개선함.

**설계 전제** 생성형 시각언어모델(VLM) 미사용. 폐쇄망, 제한된 GPU, 기존 텍스트 LLM. 특정 조직의 시스템과 운영 모델은 전제하지 않음.

## 1. 문제

### 1.1 도면 이해의 실제 난점

| 근거 | 내용 |
|---|---|
| AECV-Bench(2026) | 최신 멀티모달 모델도 도면의 문자 판독은 0.7~0.95이나 기호 개수 세기는 0.40~0.55. 문자를 정확히 읽어도 기호와 공간 관계에서 오류 발생 |
| MechVQA(ICML 2026) | 기계도면에서 주된 실패는 문자 인식이 아니라 투영 규칙 아래의 공간 관계 추론. 조립 관계와 다중 뷰 과제가 최저 성능 |
| eDOCr2(Machines, 2025) | 기계도면 치수 문자 재현율 93.75%, 문자 오류율 0.73%. 치수 문자를 형상에 연결하는 기능은 없음. 합성 데이터로 학습한 탐지기의 실제 도면 이전 성능 저하 보고 |

문자 판독은 실용 수준에 도달함. 남은 문제는 읽은 값을 형상과 연결하는 관계 복원과 그 결과의 검증임.

### 1.2 일반적인 접근의 한계

| 접근 | 한계 |
|---|---|
| OCR과 텍스트 RAG | "Ø10 ±0.1"을 읽어도 어느 구멍의 치수인지 알 수 없음 |
| 이미지 임베딩 검색 | 관련 도면은 찾으나 치수와 형상의 관계는 표현하지 못함 |
| 생성형 VLM | 공간 관계 오류(1.1절), 원본에 없는 값 생성, 좌표 미제공 |
| 탐지 모델 학습 | 도면 양식별 라벨 데이터 확보 비용. 합성 데이터의 실제 도면 이전 문제 |

## 2. 구성

| 단계 | 처리 | 산출물 |
|---|---|---|
| 1. 원본 형식별 추출 | DXF, 벡터 PDF, 스캔의 세 경로에서 문자, 선, 화살표, 형상 요소를 좌표와 함께 추출 | 기하 요소 목록 |
| 2. 기하 관계 복원 | 치수 문자, 치수선, 화살표, 치수 보조선, 형상 요소의 대응을 제약 조건 하의 전역 할당으로 결정 | 치수와 형상의 관계 |
| 3. 관계 검증 | 측정 길이와 표기 값의 일치, 뷰 간 일관성, CAD 속성과의 대조 | 확정, 후보, 기각 |
| 4. 색인 | 그림 단위 이미지 임베딩, 텍스트 BM25, 식별자 조회, 구조화 데이터와 원본 좌표 | 통합 색인 |
| 5. 응답 | 확정 정보와 출처를 기존 텍스트 LLM에 전달. 미확정 시 원본 영역 제시 | 답변, 근거 영역 |

중심 기술은 2와 3이며 이를 측정하고 개선하는 수단이 6절의 설계 원본 기반 정답 생성임. 1, 4, 5는 공개 도구로 구성하는 기본 단계임.

## 3. 원본 형식별 추출

| 원본 | 추출 | 도구 |
|---|---|---|
| DXF | 치수 개체 자체가 정의점과 측정값을 보유. 치수와 형상의 연결이 원본에 존재 | ezdxf |
| 벡터 PDF(CAD 출력본) | 선, 원호, 화살표 경로와 문자의 정확한 좌표. 치수 개체 정보는 소실되어 관계 복원 필요 | PyMuPDF(get_drawings, 문자 좌표 추출) |
| 스캔, 래스터 | 영역 분할과 치수 문자 인식, 선분과 원 검출 | eDOCr2, OpenCV(Hough 변환, 윤곽선) |
| STEP | 형상, 조립 계층, 제품 제조 정보(PMI) | Open CASCADE Technology |

세 경로의 출력은 동일한 기하 요소 스키마(종류, 좌표, 선 유형, 문자 값, 원본 형식)로 통일함. 벡터 입력이 래스터 입력보다 정확하다는 결과는 도면에서 CAD를 복원하는 연구에서도 확인됨(Drawing2CAD, ACM MM 2025: 명령 정확도 벡터 80.78%, 래스터 75.60%). 원본에 벡터 정보가 있으면 이미지로 변환하지 않음.

## 4. 기하 관계 복원

### 4.1 대상 관계

| 관계 | 의미 |
|---|---|
| 문자와 치수선 | 치수 문자가 속한 치수선 |
| 치수선과 화살표 | 치수선 양 끝의 화살표 쌍 |
| 화살표와 치수 보조선 | 화살표가 닿는 보조선 |
| 보조선과 형상 | 보조선이 연장된 형상 모서리 |
| 지시선과 형상 | 지름, 반지름, 기하공차의 지시선 끝점이 닿는 형상 |

### 4.2 후보 생성

| 기하 조건 | 판정 |
|---|---|
| 거리 | 문자와 치수선의 수직 거리, 화살표 끝과 보조선의 거리 |
| 방향 | 문자 기준선과 치수선의 평행, 화살표 방향과 보조선의 교차 |
| 정렬 | 보조선과 형상 모서리의 동일 직선 여부 |
| 선 유형 | 가는 실선(치수선, 보조선)과 굵은 실선(외형선)의 구분 |
| 뷰 소속 | 동일 도면 뷰 내부 여부 |

### 4.3 전역 할당

후보 관계마다 기하 조건으로 비용을 계산하고 제약 조건(치수 문자 하나에 치수선 하나, 치수선 하나에 화살표 두 개, 뷰 경계 내부)을 만족하는 전체 대응을 헝가리안 알고리즘 또는 정수 계획으로 결정함. 개별 근접 판정은 인접 치수가 밀집한 영역에서 오연결이 발생하므로 전역 최적화로 처리함.

## 5. 관계 검증

| 검증 | 방법 | 기각 조건 |
|---|---|---|
| 측정 길이와 표기 값 일치 | 치수선 양 끝 사이 거리에 표제란 축척을 적용한 값과 표기 값 비교. 벡터 경로는 좌표가 정확해 직접 비교 가능 | 허용 오차 초과 |
| 표기 규칙 | 치수와 공차 형식(Ø, R, M, ±, 기하공차 틀)의 문법 검사 | 문법 위반 |
| 뷰 간 일관성 | 동일 형상의 치수가 여러 뷰에 있을 때 값 비교 | 값 불일치 |
| CAD 대조 | STEP이 있으면 연결된 형상의 실제 치수(OCCT 계산)와 비교 | 값 불일치 |
| 관계 완결성 | 치수선의 화살표 쌍, 보조선과 형상 연결 여부 | 연결 누락 |

모든 검증을 통과하면 확정, 일부 미적용이면 후보, 위반이면 기각으로 기록함. 탐지 점수만으로 확정하지 않음. 측정 길이와 표기 값의 일치 검사는 도면이 스스로 정답을 내포하는 성질을 이용하므로 별도 정답 없이 자동 수행됨. 비례 척도로 그려지지 않은 치수(축척 외 표기)는 이 검사에서 제외하고 후보로 둠.

## 6. 설계 원본 기반 정답 자동 생성

### 6.1 방법

| 단계 | 처리 |
|---|---|
| 1. 원본 | STEP 모델(NIST PMI 시험 모델, DeepCAD 등 공개 모델, 도입 시 조직 보유 CAD) |
| 2. 도면 생성 | FreeCAD TechDraw로 정면도, 평면도, 측면도와 치수를 스크립트 생성. 치수마다 참조 모서리가 기록되어 치수와 형상의 정답 관계가 자동으로 남음 |
| 3. 형식 변환 | 동일 도면을 DXF, 벡터 PDF, 래스터(해상도, 번짐, 회전, 압축 조건 변화)로 출력 |
| 4. 정답 | 치수 값, 공차, 참조 형상, 좌표 |

Drawing2CAD(ACM MM 2025)는 같은 방식(FreeCAD TechDraw, STEP에서 SVG 도면 생성)으로 15만 건 이상의 도면과 CAD 쌍을 구축함. 본 구상은 이를 치수와 형상 관계의 정답 생성으로 확장함.

### 6.2 용도

| 용도 | 내용 | 단계 |
|---|---|---|
| 자동 평가 | 세 경로(DXF, 벡터 PDF, 래스터)별 관계 복원 정확도를 사람 라벨 없이 측정. 해상도와 열화 조건별 정확도 곡선 산출 | 초기 |
| 검증 기준 조정 | 5절의 허용 오차와 확정 기준을 정답 대비 오확정률로 결정 | 초기 |
| 탐지기 적응 | 화살표, 기호 탐지기를 합성 도면으로 학습. 도메인 무작위화와 소량 실제 도면 보정 병행 | 성능 한계 확인 후 |

CAD 기반 합성 데이터는 수량 증가만으로는 실제 이전 성능이 개선되지 않고 도메인 무작위화와 소량 실제 데이터 보정(50장 수준)이 성능을 크게 높인다는 산업 비전 분야의 정리가 있음(Tao and Choi, 2026). eDOCr2가 보고한 합성 학습의 이전 문제와 같은 성격이므로 탐지기 학습은 평가로 한계를 확인한 뒤 진행함.

## 7. 검색과 LLM 연결

| 구성 | 내용 |
|---|---|
| 이미지 임베딩 | 페이지와 그림(도면 뷰) 두 단위. 경량 멀티모달 임베딩 모델(텍스트와 이미지 구성 10억 매개변수 이하, 오프라인 실행) |
| 텍스트 검색 | 추출 문자와 구조화 결과의 BM25. 부품번호와 도면번호는 완전 일치 조회 |
| 구조화 데이터 | 치수, 공차, 참조 형상, 검증 상태, 원본 좌표 |
| LLM 전달 | 확정 정보와 출처. 후보와 기각 항목은 미확정으로 표시 |

| 질문 유형 | 대응 |
|---|---|
| 관련 도면 검색 | 이미지 임베딩과 텍스트 검색 |
| 도면 내 문자와 주석 | 추출 문자 조회 |
| 특정 형상의 치수와 공차 | 검증된 관계 조회 |
| 부품 간 간섭 등 3D 기하 판단 | CAD가 있으면 OCCT 형상 연산으로 계산. CAD가 없으면 범위 밖으로 처리하고 원본 제시 |
| 사전 정의되지 않은 시각 질문 | 범위 밖. 관련 그림 위치 제시 |

임베딩 차원 축소는 저장 공간과 유사도 계산을 줄이는 수단이며 인코더 연산은 줄이지 않음.

## 8. 지원 범위

| 대상 | 수준 |
|---|---|
| 관련 도면 검색 | 구현 가능. 기술도면 세부 검색 성능은 별도 측정 |
| 문자와 주석 판독 | 구현 가능(eDOCr2 기준 재현율 93.75%) |
| 표와 부품 속성 | 구현 가능 |
| 기계도면 치수와 형상 연결 | 본 구상의 중심 과제. 6절 자동 평가로 정확도 측정 |
| 계통도 연결 관계 | 확장 과제. 유형별 학습 데이터 필요 |
| 임의 그림의 자유 질의응답 | 범위 밖 |

## 9. 실험

| 실험 | 비교 | 판단 질문 | 지표 |
|---|---|---|---|
| 1. 도면 검색 | OCR과 텍스트 검색 대비 이미지 임베딩 병행 | OCR로 읽지 못한 도면을 찾는가 | Recall@5 |
| 2. 관계 복원 | OCR과 최근접 연결 대비 전역 할당과 검증 | 치수와 형상의 관계가 정확해지는가 | 관계 F1, 오확정률 |
| 3. 원본 경로 | 래스터 변환 처리 대비 원본 우선 처리 | 같은 정확도에서 연산량이 줄어드는가 | 쪽당 처리 시간, GPU 시간 |

실험 2와 3의 정답은 6절의 자동 생성 데이터로 확보함. 실제 도면 검증에는 NIST PMI 시험 도면과 eDOCr2 공개 예제를 사용함. 세 실험에서 효과가 확인되지 않으면 추가 모델을 도입하지 않음.

## 11. 선행 연구 대비 위치

| 연구 | 내용 | 본 구상과의 차이 |
|---|---|---|
| eDOCr2(Machines, 2025) | 기계도면 분할과 치수, 기하공차 OCR | 판독 단계로 사용. 치수와 형상의 관계 복원과 검증을 추가 |
| VectorGraphNET(J. Comput. Civ. Eng., 2025) | 벡터 PDF 경로를 그래프로 변환해 선 단위 의미 분할 | 벡터 원본 활용의 선례. 본 구상은 분할이 아니라 치수와 형상의 관계 복원 |
| Drawing2CAD(ACM MM 2025) | FreeCAD로 CAD에서 벡터 도면을 생성해 도면에서 CAD 복원 학습 | 같은 생성 방식을 치수와 형상 관계의 정답 생성과 평가에 사용 |
| DTRT(CVPR 2026) | 계통도의 기호와 연결 관계를 단일 모델로 추출 | 학습 기반 관계 추출. 본 구상은 기계도면에서 학습 없이 기하 제약과 검증으로 관계 복원 |
| TechDocRAG(MDPI AI, 2026) | 기술문서 조항, 표, 그림의 참조 관계 보존 검색 | 문서 단위 참조. 본 구상은 도면 내부의 기하 관계 |

새 학습 알고리즘 개발을 주장하지 않음. 차별점은 세 가지임.

1. **기하 관계 복원**: 판독한 치수를 치수선, 보조선, 형상과 전역 할당으로 연결함
2. **도면 자체 정보를 이용한 검증**: 측정 길이와 표기 값의 일치, 뷰 간 일관성, CAD 대조로 정답 없이 확정 여부를 판정함
3. **설계 원본 기반 정답 생성**: CAD에서 도면을 생성해 사람 라벨 없이 형식별 정확도를 측정하고 확정 기준을 조정함
