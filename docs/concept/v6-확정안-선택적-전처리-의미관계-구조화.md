# v6 확정안: 비정형 데이터의 선택적 전처리와 의미·관계 보존형 구조화

작성 2026-10-28. v5 초안 평가를 반영해 제출용 구상안으로 정리함. v5는 면접 대비 기술 검토 노트로 보존.

**주제:** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**핵심 메시지:** 원본에서 추출 가능한 정보는 직접 처리하고, 필요한 이미지 영역에 한해 경량 모델을 사용함. 추출한 정보는 값과 적용 조건·원본 근거를 함께 구조화해 LLM이 정확하고 효율적으로 활용하도록 함.

**설계 전제:** 외부 API 없이 공개 가중치 모델을 내부 환경에서 실행하고 GPU 자원이 제한된 상황. 특정 조직의 시스템 구성을 전제하지 않음. 제한된 GPU는 독립 과제가 아니라 해결 방안의 제약 조건.

## 0. v5 초안 대비 변경

| v5 초안 | v6 확정안 | 사유 |
|---|---|---|
| 전처리·구조화를 축 1, 제한 환경 적용을 축 2 | 전처리 / 구조화 두 축. 효율화는 각 축 안에 포함 | 주제 2의 요구는 전처리와 구조화. GPU 운영 축은 주제 1에 가까움 |
| 재렌더링 대조 검증, 오류 유형 기록 | 수치·단위·헤더 대응 확인과 불확실 영역 재처리로 요약 | 시각적 재구성 일치와 값의 의미 정확성은 다름. 구현 방법은 기술 노트에 보존 |
| 관계는 LLM이 추출하지 않음 | 명시적 관계는 규칙, 모호한 관계는 모델 추출, 미확인 연결은 미확정 | 그림의 지시 관계·조건의 적용 범위는 규칙으로 처리 불가 |
| Packet 조립 후 충분성 판정(지지·반박·불충분) | 필요한 대상·값·적용 조건 포함 여부 확인, 부족하면 추가 조회 | SURE-RAG는 후보 답변을 입력으로 검증하는 구조. 답변 전 판정에는 추가 추론 비용과 설계 복잡도 발생 |
| 양자화 비트, 모델 크기, KV 캐시, 하드웨어 3등급 | 삭제. 소형 문서 VLM과 적재 시점 처리로 반복 추론 감소까지 기술 | GPU 사양을 모르는 상태에서 구성 제안 불필요 |
| 실험군 A~D | 실험군 A·B·C | C·D 사이에 변수가 여럿이라 효과 분리 불가 |
| 지표 5분류 | 지표 4개 | 1장 전달력 |

## 1. 문제

표·이미지·기술문서를 텍스트로 변환하면 행·열, 객체·주석, 적용 조건 같은 관계가 사라짐. 반대로 원본 이미지를 질의 때마다 멀티모달 LLM에 넣으면 이미지 처리 연산과 입력 문맥이 반복 증가함.

근거: 기업 문서 약 2,000쪽으로 표·차트·본문 충실도·서식·원본 위치를 평가한 ParseBench(2026)에서 한 방식이 모든 항목에서 우수한 경우는 없었음. 표·원본 위치는 전용 파서, 차트는 문서 VLM이 강함. 따라서 자료 전체를 한 모델로 처리하기보다 요소에 따라 처리 방식을 나누고, 구조화에서는 값과 함께 헤더·적용 조건·원본 위치를 보존해야 함.

## 2. 두 축

| 축 | 핵심 기술 | 제한된 GPU와의 연결 |
|---|---|---|
| 1. 데이터 전처리 | 원본 파싱 우선 + 필요한 영역에 소형 문서 VLM | 불필요한 GPU 추론 감소 |
| 2. 데이터 구조화 | 의미·조건·관계·출처 보존 + 질문별 입력 구성 | 불필요한 토큰과 반복 이미지 처리 감소 |

## 3. 축 1. 데이터 전처리: 정보 손실과 GPU 연산 최소화

### 3.1 원본 직접 추출

텍스트 레이어가 있는 문서와 디지털 표는 파서로 텍스트·셀·메타데이터·위치를 추출함. 이 경로는 GPU를 쓰지 않음.

### 3.2 선택적 문서 VLM

스캔 페이지, 그림·차트, 복잡한 레이아웃에 한해 경량 문서 이해 모델을 적용함. 전체 페이지가 아니라 해당 영역에 적용하고, 산출물은 텍스트·표 행·열·요소 유형·위치·읽기 순서. 위치는 파서·탐지 좌표를 기준으로 기록함.

### 3.3 불확실 영역 재확인

추출된 수치·단위·헤더 대응 관계를 확인하고, 불확실한 영역에 한해 재처리(고해상도 재분석, 다른 추출기, 사람 확인)함. 확인되지 않은 값은 확정값과 분리해 보관함.

## 4. 축 2. 데이터 구조화: AI가 잘못 해석하지 않는 정보 표현

### 4.1 의미·관계 보존

| 필드 | 의미 |
|---|---|
| 대상 | 정보가 설명하는 대상 |
| 속성·관계 | 속성 또는 다른 대상과의 관계 |
| 값·단위 | 값과 단위 |
| 적용 조건 | 조건, 범위, 예외 |
| 상위 문맥 | 문서·절·표·행·이미지 계층 |
| 출처 | 원본 문서, 버전, 페이지, 셀·이미지 위치 |
| 상태 | 확인·불확실·검토 필요 |

반복되는 헤더·공통 조건은 상위 구조에 저장하고 개별 정보는 참조로 연결함.

관계 연결 원칙: 같은 행의 값, 명시된 조항·표 번호 참조처럼 명시적인 관계는 규칙으로 연결함. 그림의 지시 관계, 문장 조건의 적용 범위처럼 모호한 관계는 모델로 추출하되 확인되지 않은 연결은 확정하지 않음.

### 4.2 질문별 입력 구성

저장용(전체 정보와 원본 참조), 검색용(대상·속성·조건·상위 제목), LLM 입력용(필요한 값과 문맥)을 분리함.

| 질문 유형 | 필요한 정보 | 처리 |
|---|---|---|
| 단일 값 조회 | 대상·속성·값·조건 | 구조화 데이터 직접 조회 |
| 여러 값 비교 | 대상별 값·단위·조건 | 조회 후 규칙 비교 |
| 기술적 설명 | 관련 정보 단위·조항·출처 | LLM에 근거 전달 |
| 시각적 판단 | 구조화 정보와 원본 이미지 영역 | 필요 시 멀티모달 모델 |

질문에 필요한 대상·값·적용 조건이 포함됐는지 확인하고, 부족한 정보는 추가 조회함. 토큰 감소는 결과이지 목적이 아님.

### 4.3 제한된 자원에서의 활용

문서 등록 시점에 구조화를 마쳐 질의 시점의 반복 이미지 처리를 없애고, 간결한 근거 입력으로 로컬 LLM의 추론 부담을 줄임.

## 5. 네 가지 기술 요약

| 축 | 기술 | 내용 |
|---|---|---|
| 전처리 | 원본 직접 추출 | 텍스트·디지털 표는 파서로 처리 |
| 전처리 | 선택적 문서 VLM | 이미지·복잡한 레이아웃에 경량 모델 적용, 불확실 영역 재확인 |
| 구조화 | 의미·관계 보존 | 대상·속성·값·단위·적용 조건·출처 연결 |
| 구조화 | 질문별 입력 구성 | 필요한 값과 문맥을 복원해 로컬 LLM에 전달 |

## 6. 검증 계획

### 6.1 실험군

| 실험군 | 방식 | 비교 목적 |
|---|---|---|
| A | 일반 OCR, 텍스트 청킹 | 기본 방식 |
| B | 문서 구조 인식, 구조 보존 청킹 | 전처리 효과 |
| C | 선택적 추출, 의미·관계 구조화, 질문별 근거 구성 | 제안 방식 |

동일 LLM·질의·하드웨어. 기술 검증에서는 전처리와 구조화의 효과를 분리해 실험하고, 1장에는 세 방식의 차이를 표시함.

### 6.2 지표

| 지표 | 내용 |
|---|---|
| 정보 추출 정확도 | 수치·텍스트 값 일치율 |
| 조건·관계 보존 정확도 | 적용 조건·헤더·출처 연결 일치율 |
| 최종 QA 정답률 | 동일 질의 집합의 정답률 |
| 질의당 처리 비용 | 입력 토큰, 이미지 처리 횟수 |

구조화로 정확도가 낮아지는 경우도 기록함. 합성 데이터 결과와 실측은 구분 표기.

### 6.3 Before/After 사례

가상 산업 기술문서

| 대상 | 허용 온도 |
|---|---|
| A-17 | 80°C* |

\* 정상 운전 조건에서 적용

| 방식 | 결과 | 평가 |
|---|---|---|
| 단순 변환 | A-17 최대 온도 = 80°C | 적용 조건 손실 |
| 제안 구조화 | A-17 · 허용 온도 80°C · 정상 운전 · 원문 표·각주 | 값과 조건을 함께 보존 |

두 방식의 입력 토큰 실측을 함께 표시함.

## 8. 1장 구성

제목: 비정형 데이터의 선택적 전처리와 의미·관계 보존형 구조화

- 문제: 구조 손실, 반복 이미지 처리, 불필요한 입력 문맥

- 축 2 데이터 구조화: 의미·관계 보존, 질문별 입력 구성, 제한된 자원에서의 활용

특정 내부 업무·시스템 미언급. 공개된 일반 기술문서·표·이미지 예시 사용.
