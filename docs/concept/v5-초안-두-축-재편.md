# v5 초안: 두 축 재편 — 전처리·구조화와 제한 환경 적용 (면접 대비 기술 검토 노트)

작성 2026-10-28. v4 수정안을 두 축으로 재편하고 논문 정독 결과를 반영한 초안. 제출용 구상안으로는 채택하지 않음(범위 과다, 주제 1에 근접). 제출용은 [v6 확정안](v6-확정안-선택적-전처리-의미관계-구조화.md). 이 문서는 면접 대비 기술 검토 노트로 보존.

**주제:** 비정형 데이터(표, 이미지 등)를 AI가 효율적으로 이해하고 활용할 수 있도록 하기 위한 데이터 전처리 및 구조화 방안

**두 축**

- 축 1. AI가 효율적·효과적으로 이해하는 비정형 데이터의 전처리·구조화
- 축 2. 제한된 GPU·폐쇄망·온프레미스·엣지 환경에서 구조화 결과를 LLM에 적용하는 방법

**설계 전제:** 외부 API 없이 공개 가중치 모델을 내부 환경에서 실행하고 GPU 자원이 제한된 상황. 특정 조직의 실제 시스템 구성을 전제하지 않음.

## 1. 문제 정의

두 가지 질문에 답해야 함.

1. 표·이미지·기술문서의 행·열, 객체·주석, 적용 조건 같은 관계를 잃지 않으면서 AI가 쓸 수 있는 형태로 어떻게 바꾸는가.
2. 그 결과를 GPU가 적고 외부 연결이 없는 환경의 LLM에 어떻게 넣어 정확도와 비용을 함께 만족하는가.

페이지 이미지를 질의 때마다 멀티모달 LLM에 넣는 방식은 두 질문 모두에서 불리함. 한 장이 1,000토큰 이상이고(SmolVLM 1,024, Arctic-Extract 약 1,000), 작은 모델일수록 표 구조 오류·환각이 커지며(MMTabReal), 근거 위치를 모델이 제시하지 못함(ViDoRe V3 위치 F1 0.07~0.09). 반대로 Markdown 변환으로 끝내면 적용 조건·헤더 관계가 사라져 집계·비교 질의에서 틀림(TableRAG, DesignQA).

## 2. 전체 구조: 적재 시점과 질의 시점의 분리

| 시점 | 단계 | 산출물 |
|---|---|---|
| 적재(배치, GPU 유휴 시간) | 요소 유형별 라우팅, 추출(파서 또는 영역 한정 소형 VLM), 정규화, 검증(형식·관계·원본 근거), 임계값 미달 영역 재처리 | 정보 단위(DB, 검색 인덱스, 원본 영역) |
| 질의(상시, 소형 생성 모델) | 질문 유형 판별, 검색·조회(DB 연산 또는 서술문 검색과 재순위), Evidence Packet 조립, 충분성 판정(지지·반박·불충분) | LLM 생성 또는 보류 |

무거운 처리는 모두 적재 시점으로 옮기고, 질의 시점에는 검색·조회·소형 모델 생성이 남음. 같은 페이지를 다시 해석하지 않음.

## 3. 축 1. 전처리·구조화

### 3.1 요소 유형별 라우팅

| 요소 | 기본 경로 | 소형 VLM 사용 | 근거 |
|---|---|---|---|
| 디지털 텍스트·목록·제목 | PDF 텍스트 레이어 파서(CPU) | 없음 | Docling CPU 0.6~2.2쪽/초 |
| 디지털 표 | 파서 + 표 구조 모델(CPU) | 구조 불명확 영역 | ParseBench 표: 전용 파서 85~86 |
| CAD·DXF·STEP | 네이티브 파서, LLM 미사용 | 없음 | P&ID DXF F1 97.5 vs 비전 LLM 55.9 |
| 스캔 페이지 | 영역 탐지 후 영역별 소형 문서 VLM | 해당 영역 | BLUEPRINT 영역 한정 nDCG 0.563 vs 전체 페이지 OCR 0.21~0.29 |
| 차트·그림·다이어그램 | 캡션·범례·축 텍스트는 파서, 데이터·주석은 소형 VLM | 해당 영역 | ParseBench 차트: 전용 파서 1~6 vs VLM 65 |
| 도면 표제란·주기 | 영역 탐지 후 영역별 추출, 기호는 특화 소형 모델 | 해당 영역 | Florence-2 0.23B F1 61.5 vs GPT-4o 35.5 |
| 그림 안 텍스트 | 파서가 버리므로 그림 영역에 소형 VLM | 해당 영역 | Docling 보고서(그림 내 텍스트 폐기) |

원칙: 텍스트 레이어가 있으면 이미지 모델을 거치지 않음. 이미지 모델은 영역 크롭 단위로 호출하고 전체 페이지를 넣지 않음(소형 모델은 긴 문맥에서 불안정, SmolVLM).

### 3.2 추출 단계

1. **원본 분석·직접 파싱:** 파일 형식, 텍스트 레이어, 표 구조, 영역 좌표 확인. 직접 추출 가능한 요소는 GPU를 쓰지 않음.
2. **영역 한정 소형 문서 VLM:** 스캔·차트·그림·도면 영역에 2~3억 파라미터급 문서 모델 적용. 산출물은 텍스트, 표 행·열, 요소 유형, 위치 좌표, 읽기 순서. 위치 좌표는 모델 출력이 아니라 파서·탐지기의 좌표를 기준으로 기록.
3. **정규화:** 숫자·단위 분리, 자료형 지정, 원문 식별자·용어 보존. 단위 환산·용어 통합은 검증 가능한 규칙이 있을 때 수행.
4. **불확실 영역 재처리:** 3.3의 검증 임계값 미달 영역에 한해 고해상도 재분석, 다른 추출기, 상위 모델, 사람 확인 순으로 적용.

### 3.3 검증

| 층 | 확인 사항 | 방법 |
|---|---|---|
| 형식 | 필수 필드, 자료형, 단위, 표 행·열 수, 좌표 유효성 | 규칙 |
| 관계 | 헤더↔셀, 주석↔객체, 조건↔값 연결, 단위 일관성 | 규칙 + 구조 비교 |
| 원본 근거 | 추출값과 원본 셀·문구·이미지 영역의 대응 | 추출물을 재렌더링해 원본 크롭과 대조(구조 일치 + 문자 오류율), 임계값 미달 영역에 한해 재처리 |

- 비교 기준은 항상 원본 영역. 추출물끼리 비교하지 않음(RaV-IDP).
- 검증 결과는 점수가 아니라 오류 유형(셀 병합 오류, 헤더 누락, 수치 전사 오류 등)으로 기록해 재처리 경로를 유형별로 선택(DOCR-Inspector).
- 문자열 일치가 아니라 값·단위·헤더 대응을 기준으로 판정. 헤더 평탄화 같은 무해한 차이는 통과, 소수점·부호 누락은 실패(Beyond String Matching).
- 검증 통과 전 정보는 확정값과 분리. 원본 대조로 판정할 수 없는 내용은 미확정 유지.

### 3.4 정보 단위 스키마

| 필드 | 의미 |
|---|---|
| Subject | 정보가 설명하는 대상 |
| Attribute / Relation | 속성 또는 다른 대상과의 관계 |
| Value / Unit | 값과 단위 |
| Qualifier | 적용 조건, 범위, 예외, 시점 |
| Parent Context | 문서·절·표·행·이미지 계층 |
| Provenance | 원본 문서, 버전, 페이지, 셀·이미지 좌표 |
| Validation Status | 확인·불확실·검토 필요 |

- 다단 헤더는 속성 경로("최대 온도 > 비상")로 저장(ATG, ASTRA). 반복되는 헤더·공통 조건은 상위 구조에 두고 참조로 연결.
- 관계는 LLM이 추출하지 않음. 표 구조(같은 행·열), 조항의 참조("표 1 참조"), 식별자 일치 + 범위·조건·버전 확인 규칙으로 결정. 개방형 70B급도 관계 추출 F1이 엔티티보다 12~25점 낮음(Doc2DB-Bench).
- 스키마는 작게 유지. 문서 전체를 큰 스키마 하나로 뽑는 방식은 스키마 폭에 비례해 실패(ExtractBench).
- 이미지 정보는 일반 캡션이 아니라 질문에 쓰일 속성(값·라벨·관계) 중심으로 추출. 사람이 검증한 텍스트 치환이 모델 입력으로 가장 유리(MMTabReal).

### 3.5 저장·검색·입력 분리

- **저장:** 표는 관계형 테이블에 스키마 설명과 함께. 비교·집계는 DB 연산으로 계산(TableRAG). 원본 파일·영역 이미지는 별도 보존.
- **검색:** 정보 단위마다 대상·속성·조건·상위 제목을 담은 서술문을 생성해 키워드 검색 기본, 소형 임베딩 검색 결합, 소형 텍스트 재순위 모델 적용. 재순위는 텍스트 측에서 효과가 크고(ViDoRe V3 +13.2, GEMS-RAG −4.65) 시각 재순위는 효과 없음.
- **그래프:** 조항과 표·그림의 참조, 표와 행의 계층을 그래프로 두고 검색 확장 1홉에 사용. 삼중항을 프롬프트에 넣지 않음(2607.16604). 범용 GraphRAG는 사실 조회에서 기본 RAG보다 못하고 토큰이 수십 배(GraphRAG-Bench).
- **입력:** 질문에 필요한 단위를 골라 상위 문맥·출처를 복원한 Evidence Packet.

### 3.6 질문 유형별 Packet과 충분성 판정

| 질문 유형 | 필요한 정보 | 처리 |
|---|---|---|
| 단일 값 조회 | 대상·속성·값·조건 | DB 직접 조회, LLM은 문장화 담당 |
| 여러 값 비교·집계 | 대상별 값·단위·조건 | DB 연산, 규칙 비교 |
| 기술적 설명 | 관련 단위·조항·출처 | LLM에 근거 전달 |
| 시각적 판단 | 구조화 정보 + 원본 영역 | 필요 시 멀티모달 모델에 영역 크롭 입력 |

Packet 조립 후 근거 집합 전체에 대해 지지·반박·불충분을 판정함(SURE-RAG). 개별 문단 점수의 최대·평균이 아니라 집합 단위로 판단해 빠진 조건·반박 근거를 놓치지 않음. 불충분이면 추가 검색 또는 원본 영역 확인, 그래도 부족하면 답변 보류. 보류 비율과 오답 위험의 상충은 지표로 관리.

## 4. 축 2. 제한 환경에서의 LLM 적용

### 4.1 운용 원칙

1. 비용은 적재 시점으로 옮긴다. 질의 시점에는 검색·조회·소형 생성을 남긴다(BLUEPRINT, RAGAL, 철도 사례 공통).
2. 모델 크기보다 검색 품질을 먼저 높인다. 의도 라우팅과 임베더 조정으로 62%에서 81%, recall@10 0.663에서 0.850(RAGAL). 작은 생성 모델이 근거 충실도에서 큰 모델보다 나은 경우가 있음(RAGnaroX).
3. 압축(시각 토큰·가중치·KV 캐시)은 층마다 따로, 자체 질의 집합으로 실측해 고른다. 압축률은 성능을 예측하지 못함(KV 벤치마크).

### 4.2 자원 배치

| 시점 | 구성 | 근거 |
|---|---|---|
| 적재 | CPU 파서 + 영역 탐지 + 2~3억 파라미터 문서 VLM(4비트 가능) + 재렌더링 검증. 배치 대기열, GPU 유휴 시간 | 4비트 소형 VLM OCR 손실 약 3%, 2비트 15%(SPEED-Q). Granite-Docling 가중치 약 0.5GB(BF16), 추론 메모리는 이보다 큼 |
| 적재(예외) | 임계값 미달 영역에 한해 상위 모델 또는 사람 | 선택적 재처리 비용 −71%(RaV-IDP). 비용 13배 모델이 더 정확하지 않음(ParseBench) |
| 질의 | 4~8B 양자화 생성 모델 + 소형 임베딩 + 소형 교차 인코더 재순위·충분성 판정 | RTX 4090 1장 Qwen3-4B q8 7.5GB, 지연 2.5초 미만(RAGnaroX). 8GB GPU 운영(RAGAL) |
| 질의(입력) | 쪽당·질의당 토큰 상한, 구조화 단위를 입력, 원본 영역은 시각 판단 질문에 한해 크롭으로 | 쪽당 토큰 고정 시 120쪽까지 메모리 일정(DocSLM) |

### 4.3 환경 등급별 배치

| 등급 | 예 | 적재 | 질의 |
|---|---|---|---|
| 엣지·CPU | GPU 없는 노트북, 8GB GPU | CPU 파서 중심, 소형 문서 VLM은 CPU 또는 야간 배치 | 2~4B 4비트 생성, 조회형 질문 위주 |
| 온프레미스 단일 GPU | 24GB 1장 | 전 경로 가능, 배치 시간대 분리 | 4~8B 양자화 생성 + 재순위 |
| 공유 GPU·다중 사용자 | GPU 소수를 여러 서비스가 공유 | 적재 작업에 자원 예산 배정, 서비스 추론과 분리 | 입력 토큰 상한이 동시 처리 수를 결정. 자주 조회되는 단위는 KV 사전 계산 검토 |

### 4.4 압축의 층별 선택

| 층 | 적용 | 조건 | 근거 |
|---|---|---|---|
| 시각 토큰 | 픽셀 중복 제거(무손실) 우선, 주의 희소화는 지연 개선용 | 토큰 영구 삭제는 문서 OCR 파괴 | PixelPrune 23~50% 감축·정확도 −0.2~−0.9, FastOCR 5% 주의 시 98% 유지, 삭제형 72.8에서 10.7 |
| 가중치 | 적재 모델 4비트, 생성 모델 4~8비트 | 2비트는 검증 실패 증가로 총비용 역전 가능 | SPEED-Q, RAGAL(3비트를 VRAM에 전부 올린 쪽이 CPU 넘침보다 정확·빠름) |
| KV 캐시 | 조회형 질문에 4비트 KV 양자화, 자주 쓰는 단위의 KV 사전 계산 | 설명·요약형은 전체 캐시 유지 | KV 벤치마크(요약 −15~−35%), FusionRAG TTFT 2.7~9.4배 |

경량화·양자화 자체는 주제가 아님. 구조화 결과를 작은 모델에 넣기 위한 조건으로 다룸.

### 4.5 폐쇄망 실행

- 모델 가중치·토크나이저·라이브러리는 승인 절차로 사전 반입. 외부 API를 필수 구성 요소로 두지 않음.
- 라이선스·공급망 기준으로 도입 가능 모델 범위를 정하고, 후보 비교는 자체 문서·질의 집합으로 수행.
- 서빙 기본값(문맥 창, 출력 길이)도 모델 동작의 일부로 관리(RAGAL).
- 사람 검토 경로: 저신뢰 단위는 보류 상태로 보존하고 승인 후 반영. 개방형 모델로 운영하는 환경에서는 필수(Chalmers SMC 2025).

## 5. 차별화

1. **요소 유형별 선택적 전처리:** 파서가 강한 요소와 VLM이 강한 요소가 다르다는 점(ParseBench)을 설계에 반영. 통합 모델 하나로 모든 페이지를 처리하지 않음.
2. **검증 가능한 의미·관계 보존:** 재렌더링 대조와 오류 유형 기록으로 추출 신뢰도를 단위별로 관리. 관계는 구조·참조 규칙으로 결정.
3. **질문별 최소 충분 근거와 보류:** 필요한 단위를 입력하고 충분성 판정으로 보류를 결정. 토큰 감소는 결과이지 목적이 아님.
4. **적재·질의 분리로 제한 환경 대응:** 무거운 처리를 배치로 옮기고 질의 시점은 소형 모델로. 환경 등급별 배치와 층별 압축 실측.

개별 기술은 기존 연구에 기반함. 차별점은 정확도와 연산 효율을 함께 다루는 전처리·구조화·입력 구성·자원 배치의 연계 설계.

## 6. PoC 계획(구상안 확정 후 착수)

### 6.1 비교 실험

| 실험군 | 전처리 | 구조화·입력 |
|---|---|---|
| A. 기본 | OCR | 고정 길이 청크 |
| B. 통합 모델 | 모든 페이지 문서 VLM | Markdown 청크 |
| C. 구조화 | 문서 VLM | 정보 단위 + Packet |
| D. 제안 | 요소별 라우팅 + 영역 한정 VLM + 검증 | 정보 단위 + Packet + 충분성 판정 |

동일 LLM·질의·하드웨어. B·C 차이로 구조화 효과, C·D 차이로 전처리 경로 효과.

### 6.2 지표

| 분류 | 지표 |
|---|---|
| 전처리 | 값 일치율, 표 구조 F1, 오류 유형 분포 |
| 구조화 | 조건·헤더 연결 정확도, 출처 일치율 |
| 검색·입력 | 근거 완전성(필요 단위가 모두 포함), 오염률(무관 단위 비율) |
| AI 활용 | QA 정답률, 근거 충실도, 보류 적절성(보류율 대비 오답 위험) |
| 자원 | 문서당 전처리 시간·GPU 메모리, 질의당 입력 토큰·첫 토큰 지연, 재사용 횟수 반영 총비용 |

구조화로 정확도가 낮아지는 경우도 기록. 합성 데이터 결과와 실측은 구분.

### 6.3 Before/After 사례

동일 표·이미지·문서에서 기본 방식은 적용 조건을 놓쳐 틀리고, 제안 방식은 조건을 보존해 올바른 근거를 고르는 사례 1건과 두 방식의 입력 토큰 실측을 1장에 포함.
