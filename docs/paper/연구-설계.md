# 연구 설계 v1: 질문에 따른 기술 문서 표현 선택

작성 2026-11-02. [논문 초고](논문-초고.md)의 중심을 옮기고 심사에서 지적될 항목과 추가 실험을 정리함. 수치는 모두 현재 240문항(개발 세트) 기준이며 미사용 평가 세트 결과가 아님.

## 1. 연구 질문

가제: Query-Adaptive Representation of Technical Documents for Question Answering with Small Language Models (소형 언어 모델의 기술 문서 질의응답을 위한 질문 적응형 표현 선택)

기존 초고는 "관계 그래프 직렬화가 소형 텍스트 모델의 정답률을 높이는가"를 다룸. 도면을 그래프로 바꿔 언어 모델에 주는 방식 자체는 선행 연구가 있으므로 독창성 근거가 되기 어려움. 연구 질문을 다음으로 바꿈.

> 기존 텍스트 언어 모델에 기술 문서를 줄 때 어떤 정보는 원본 텍스트로 두고 어떤 정보는 관계 그래프로 구조화해야 정확도와 입력 비용이 함께 개선되는가.

검증할 가설 세 가지.

| 번호 | 가설 | 판정 기준 |
|---|---|---|
| H1 | 관계 질문에서 관계 정보가 정답률의 주된 원인임 | 같은 추출 결과의 objects 대비 relations·full의 차이, 대응 비교 구간이 0을 포함하지 않음 |
| H2 | 질문 문장에서 정한 표현 선택이 단일 표현보다 정확하고 입력이 짧음 | 미사용 평가 세트에서 선택 규칙이 full 고정 이상 정답률, 평균 입력 길이 감소 |
| H3 | 효과가 CPU 실행 공개 가중치 모델 여러 종에서 유지됨 | 모델 2~3종에서 H1·H2 방향이 같음 |

## 2. 선행 연구와의 차이

| 연구 | 그래프 출처 | 모델 | 평가 | 본 연구와의 차이 |
|---|---|---|---|---|
| PIDQA (Gupta 외, MAKE 7(2):39, 2025) | 합성 P&ID 500장 영상에서 기호·선 인식 후 속성 그래프 | gpt-3.5-turbo가 질문을 Cypher 질의로 변환 | 64,000문항, 4유형(단순 개수, 공간 개수, 공간 연결, 값) | 질의 언어 변환 방식. 원본 텍스트 기준선과 표현 선택 없음. 표·본문 문서 없음 |
| ChatP&ID (AIChE J., 2026, arXiv 2603.22528) | DEXPI XML에서 pyDEXPI로 생성. 영상 추출은 실험하지 않음 | 상용 모델 8종, 로컬 모델(8B 등) | P&ID 1장(DEXPI 예제, 본 연구의 C01과 같은 도면) 19문항, 언어 모델 판정 채점 | 설계 파일을 전제로 함. 그림에서 추출하지 않음. 질문별 도구 선택을 구현했으나 실험에서는 평가하지 않음 |
| VGBench (EMNLP 2024) | 벡터 그래픽 코드(SVG 등) | 대형 모델 | 벡터 그래픽 이해·생성 | 기하 기본 요소의 텍스트 표현이 이해에 쓰일 수 있다는 근거. 관계 복원과 문서 질의응답은 다루지 않음 |
| 본 연구 | 그려진 도면(벡터 기하, 래스터·스캔)에서 규칙 기반 추출 | CPU 실행 8B급 공개 가중치 모델, 상용 소형 모델 | 정확 일치 채점, 문서·질문 종류별 분석 | 원본 텍스트와 관계 표현의 조건 분리, 질문 문장 기반 표현 선택, 표·본문 문서 포함, 생성형 시각 언어 모델 미사용 |

주장할 기여는 두 가지로 한정함.

1. 관계 정보를 보존하는 경량 구조화 경로. 벡터 원본의 기하 정보와 스캔 영상에서 요소·연결을 복원하고 원본 좌표를 남긴 텍스트로 직렬화함.
2. 질문에 따른 표현 선택과 그 검증. 같은 추출 결과에서 관계 정보를 단계적으로 더한 조건 분리 실험으로 정답률의 원인을 분리하고, 질문 문장으로 정한 선택 규칙을 미사용 평가 세트에서 잼.

질문별 선택 자체는 새로운 개념이 아니므로 비교 대상(항상 full, 항상 ocr, 항상 both, 문서 경로 규칙, 문항마다 맞는 쪽을 고른 상한)을 함께 보고하고 차이를 수치로 제시함.

## 3. 현재 결과(개발 세트)

### 3.1 연결 추출

| 조건 | 재현율 | 정밀도 | F1 | 요소 라벨 대응 |
|---|---|---|---|---|
| C01 벡터 | 1.00 | 1.00 | 1.00 | 0.97 |
| C01 200 dpi | 0.73 | 0.35 | 0.48 | 0.80 |
| C01 스캔 | 0.71 | 0.27 | 0.39 | 0.90 |
| C02 벡터 | 0.50 | 0.23 | 0.32 | 0.59 |
| C03 벡터 | 0.44 | 0.44 | 0.44 | 1.00 |
| 5조건 평균 | 0.677 | 0.459 | 0.524 | 0.852 |
| 증류 도면 2장 포함 7조건 평균 | 0.615 | 0.472 | 0.512 | - |

정밀도는 배관 정답 범위 밖인 계측 신호선 쌍을 분모에서 뺀 값. 재현율보다 정밀도가 낮아 잘못 만든 연결이 많음. 표의 출처 `examples/public-documents/pid/output/current/prf.md`, 생성 `pid/prf.py`.

### 3.2 질의응답

| 모델 | ocr | full | 질문별 선택(규칙) | 상한 |
|---|---|---|---|---|
| 공개 가중치 8B, CPU | 37.5% | 65.0% | 66.2% | 68.8% |
| 상용 소형 | 39.2% | 58.8% | 64.2% | 66.2% |

선택 규칙의 평균 입력은 6,079자로 full(8,006자)의 76%. 규칙은 개발 세트를 본 뒤 정했으므로 이 값은 개발 세트 성능임. 이전 retrieved 결과는 정답 누출(4절)로 비교에서 뺌.

정답 그래프 입력 조건: C01 벡터 추출 그래프는 정답과 일치(재현율·정밀도 1.00)하고 C01 래스터·스캔 문항은 벡터와 같은 질문임. 따라서 C01 벡터의 정답률(8B full 91%)이 래스터·스캔 문항의 정답 그래프 조건 값이 되며, 래스터 49%·스캔 47%와의 차이 42~44%p가 추출 오류에서 온 몫, 정답 그래프에서도 남는 9%p가 모델 추론의 몫임.

## 4. 심사 지적 예상 항목과 조치

| 항목 | 현재 상태 | 조치 | 상태 |
|---|---|---|---|
| 검색 조건의 정답 누출 | 부분 그래프 검색이 문항의 focus 필드를 씀(25문항은 정답과 같음, 34문항은 질문에 없음). 계기 질문 예시 "(예: PI, TIC)"에 정답 PI 포함 | 질문 문장에 적힌 그래프 요소 이름으로 검색. 예시를 자료에 없는 "(예: FIC, LT)"로 교체. 이전 retrieved 결과 폐기 | 코드 완료, 재실행 필요 |
| 관계 정보의 효과 미분리 | ocr과 full의 비교 | 같은 추출 결과로 ocr, objects, relations, full 비교 | 코드 완료, 재실행 필요 |
| 사후 규칙 | 질문 종류 표시를 보고 고른 64~65% | 질문 문장과 입력 경로를 입력으로 쓰는 규칙(`select_repr.py`)으로 확정 | 완료(개발 세트 값) |
| 추출 정밀도 미보고 | 재현율 위주 | 정밀도·F1 표 추가 | 완료 |
| 독립 평가 데이터 없음 | 같은 240문항으로 네 차례 개선 | 도면 단위로 개발·평가 분리, 외부 데이터로 평가 세트 구성(5절) | 미착수 |
| 도면 간 일반화 | C01 우수, C02·C03·증류 도면 하락 | PID2Graph 실물 도면으로 추출 F1 측정, 평가 세트 결과를 도면별로 보고 | 스크립트 있음, 데이터 내려받기 필요 |
| 자원 효율 | CPU 실행 확인 | 전처리 시간, 최대 메모리, 입력 토큰, 응답 지연을 벡터·스캔별로 측정 | 미착수 |
| 시각 언어 모델 비교 | 없음 | 소형 로컬 시각 언어 모델 1종을 비교군으로 실행(시스템 구성 요소가 아님) | 선택 사항 |

## 5. 평가 데이터

원칙: 개발 세트는 현재 15건·240문항으로 고정하고 규칙·직렬화를 더 고치지 않음. 평가 세트는 개발에 쓰지 않은 도면으로 구성하고 도면 단위로 나눔. 평가 세트로 직렬화나 규칙을 바꾸지 않음.

| 세트 | 자료 | 정답 | 용도 | 확인 사항 |
|---|---|---|---|---|
| A. PIDQA | 합성 P&ID(Dataset-P&ID 500장 중 50장) | 질문·정답 CSV(CC0), Cypher 질의 | 질의응답 평가 400문항(4유형 × 도면당 2문항 층화) | 도면 이미지는 별도 배포(구글 드라이브), 사용 조건 확인 필요 |
| B. PID2Graph | 실물 P&ID(OPEN100) | graphml(기호 상자·배관 간선), CC BY-SA 4.0 | 연결 추출 정밀도·재현율·F1의 도면 간 일반화 | 9.3 GB, 노트북에서 내려받기 |
| C. 개발 세트 | 현재 15건 | DEXPI XML, 생성 스크립트, 원문 대조 | 조건 분리 분석, 오류 분석 | 없음 |

PIDQA의 질문은 기호를 1~32번 분류로 부름. 현재 추출은 규칙 기반이라 기호 32종을 분류하지 않으므로 두 설정으로 나눔.

- 기호 정답 제공: Dataset-P&ID의 기호 상자·분류를 주고 선 추적·연결 복원·직렬화를 본 방법으로 수행. 관계 복원과 표현 선택의 효과를 재는 주 실험
- 기호 분류 포함: 기호 분류까지 하는 설정은 본 연구 범위 밖으로 명시

PIDQA 질문은 템플릿 문장이므로 선택 규칙의 단서 어휘가 템플릿에 맞춰지지 않도록 규칙을 평가 세트 전에 고정함(커밋 기록으로 확인 가능).

## 6. 실험 목록

| 순서 | 실험 | 입력 조건 | 모델 | 실행 위치 |
|---|---|---|---|---|
| 1 | 개발 세트 조건 분리 | ocr, objects, relations, full, retrieved | 8B 공개 가중치 | 노트북 CPU(`run_ablation.sh`, 약 750회 호출) |
| 2 | PIDQA 변환·평가 세트 구축 | - | - | 노트북(데이터 내려받기), 변환 코드는 저장소 |
| 3 | 평가 세트 질의응답 | ocr, objects, relations, full, both, 선택 규칙 | 8B·7B·14B급 공개 가중치 | 노트북 CPU |
| 4 | PID2Graph 추출 평가 | - | - | 노트북(`examples/pid2graph/run_all.py`) |
| 5 | 비용 측정 | 전처리 시간·메모리, 입력 토큰, 응답 지연 | 8B | 노트북 |
| 6 | 같은 입력 길이 예산 비교 | objects, relations, 선택 규칙을 같은 문자 수로 자름 | 8B | 노트북 |

보고 방식: 문항 평균과 도면 평균을 함께, 질문 문장 묶음 재표집 95% 구간, 조건 간 대응 비교, 실패 유형(추출 누락, 추출 오류, 모델 추론 오류).
