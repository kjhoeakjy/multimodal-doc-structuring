# 연구 설계 v3: 기술 도면을 언어 모델에 넘기기 위해 구조화를 어디까지 해야 하는가

작성 2026-11-04. [v2](archive/연구-설계-v2.md)의 본 주제(추출 오류의 영향)는 유지하고, 다음 세 가지를 바꿈.
1. "소형 언어 모델"을 "언어 모델"로 넓히고 모델 능력별 비교(공개 가중치 8B·14B, 상용 소형·중형)를 독립 연구 질문으로 둠. 8B에서 연결 의존 문항이 정답 그래프에서도 22%에 머무는 바닥 효과가 확인되어, 추출 오류의 효과와 모델 추론 한계를 분리해야 함.
2. 11-03~04 결과로 핵심 주장을 바꿈. 간선 재현율·정밀도는 정답률을 예측하지 못하고(상관 0.23·0.01), 문항 근거가 문맥에 남은 비율(근거 보존율)이 정답률을 거의 전부 설명함(상관 0.99). 요소 문자의 복원과 귀속이 1순위, 간선 누락이 2순위, 간선 정밀도·위상 오류는 무영향.
3. 폐쇄망 제조 환경(외부 API 사용 제한, 자체 GPU의 공개 가중치 모델, 텍스트 전용 입력)을 동기로 두고, 본문을 추출 품질, 평가 지표, 사전 계산, 파인튜닝의 네 단계로 구성함. 파인튜닝은 GPU가 확보될 때 넣는 조건부 축임.

## 1. 배경과 동기

제조·항공·방산 현장은 자료 반출 제한으로 외부 API 모델을 쓰지 못하고, 사내 GPU에 공개 가중치 모델을 두어 텍스트 입력만 처리하는 경우가 많음. 도면을 이런 모델에 넣으려면 기호·문자·연결을 구조화한 그래프(온톨로지 인스턴스)로 바꿔야 하며, 구조화 오류가 답에 그대로 전파됨. 산업계 백서(Palantir, Institutional Sovereignty in the Age of AI; Evals as the Substrate for Sovereign AI; AutoResearch and the Fine-Tuning Ontology, 2026)는 기관이 보유해야 할 자산을 온톨로지, 평가 기준, 절차 계층, 가중치 순으로 두고, 가중치 조정은 마지막 지렛대라고 봄. 같은 문서는 기밀·핵심 자료에만 자체 호스팅을 권하고 일상 업무에는 무보존 계약의 외부 모델도 선택지로 두므로, 외부 API 배제를 절대 조건으로 쓰지 않고 자료 반출이 막힌 업무에 한정함. 본 연구는 이 순서를 기술 도면 질의응답에 적용해, 각 단계가 어떤 구조화 오류를 흡수하고 어떤 오류는 흡수하지 못하는지를 같은 오류 곡선으로 측정함. 백서의 수치는 가상 예시이므로 성능 근거로 인용하지 않고 설계 틀(온톨로지 단면 선택, 도면 단위 분리, 실제·합성 사례 혼합, 사전 임계값 평가)만 참고함.

## 2. 연구 질문

가제: How Much Structure Is Enough? Extraction Depth for LLM Question Answering on Engineering Drawings (구조화는 어디까지 필요한가: 기술 도면 언어 모델 질의응답을 위한 추출 깊이)

중심 질문: 도면을 언어 모델에 넘기기 위해 구조화를 어디까지 해야 하는가. 답의 형태: 요소·문자·귀속은 정확해야 하고, 위상은 재현율 중심으로 충분하며, 다단계 관계는 모델에 맡기지 않고 코드로 미리 계산한다. 필요한 깊이는 문항 종류와 모델 능력에 따라 달라진다. 효과가 없다는 결론은 "차이가 ±몇 %p 이내"처럼 구간으로 쓴다.

| 번호 | 질문 | 측정 | 상태(11-04) |
|---|---|---|---|
| Q1 | 구조화 오류 9종(연결 누락, 거짓 연결, 라벨 맞바꿈, 분기점 분할, 요소 병합, 문자 오독, 요소 누락, 문자 귀속, 복합) 가운데 무엇이 정답률을 떨어뜨리는가 | 오류 비율별 정답률 곡선, 종류 간 기울기 | 상용 소형 완료, 8B 진행 |
| Q2 | 간선 재현율·정밀도, 문자 복원율, 근거 보존율 가운데 무엇이 정답률을 예측하는가 | 설정 단위 상관, 근거 유무별 정답률 | 상용 소형 완료(39설정) |
| Q3 | 질문 종류(속성, 연결)와 모델 능력(8B, 14B, 상용 소형, 상용 중형)에 따라 치명적 오류 축이 다른가 | 종류별 곡선, 모델 사다리 | 상용 소형 완료, 8B 일부, 14B·중형 대기 |
| Q4 | 실제 추출(같은 도면의 래스터·스캔, 실물 도면 12장)은 통제 오류 곡선 위에 놓이는가 | 실측 지표와 정답률, 오답 원인 분류 | C01 완료, 실물 12장 주석 완료 |
| Q5 | 공개 가중치 모델의 격차를 줄이는 데 절차 계층(경로·도달 사전 계산 코드)과 가중치(파인튜닝) 중 무엇이 얼마나 기여하며, 어떤 오류는 둘 다로 복구되지 않는가 | 입력(원본 그래프, 사전 계산) × 가중치(기본, 파인튜닝) 2×2를 같은 오류 설정에서 측정 | 사전 계산 축은 CPU로 진행, 파인튜닝 축은 GPU 확보 시 |

기여
1. 기술 도면 그래프 질의응답에서 구조화 오류 9종의 영향을 통제 실험으로 정량화함(합성 오류와 실제 추출 오류 대조)
2. 간선 중심 추출 평가(재현율·정밀도·F1)가 하류 질의응답을 예측하지 못함을 보이고, 근거 보존율을 평가 지표로 제시함
3. 질문 종류와 모델 능력에 따라 치명적 오류 축이 다름을 보이고, 모델을 키우면 풀리는 한계(연결 추론)와 풀리지 않는 오류(문자 복원·귀속)를 분리함
4. 코드(사전 계산)와 가중치(파인튜닝)가 각각 흡수하는 오류의 범위를 같은 잣대로 비교함(파인튜닝 축은 조건부)

## 4. 실험 설계

### 4.1 테스트베드

| 테스트베드 | 정답 그래프 | 문항 | 용도 | 상태 |
|---|---|---|---|---|
| T1. DEXPI C01 | 벡터 추출 그래프(정답과 일치) | 속성 43문항, 연결 의존 36문항 | 오류 통제, 실제 추출(200 dpi·스캔) 대조 | 완료(상용 소형), 진행(8B) |
| T3. PID2Graph OPEN100 | graphml 정답 + 태그 주석(계기 전부, 장비) | 장비·계기 태그 기반 자동 생성 | 실물 12장 반복, 도면 단위 구간 | 주석 12장 완료, 문항 생성 대기 |
| T2. PIDQA | Dataset-P&ID 주석 | 연결·개수 | 규모 확대(선택) | 보류 |

실물 도면의 밸브는 수동 밸브에 태그가 없고 제어 밸브 태그는 옆 계기 원에 있어, 문항은 장비·계기 태그를 기준으로 만들고 밸브는 개수 문항에만 씀.

### 4.2 오류 종류

| 종류 | 방법 | 변하는 지표 |
|---|---|---|
| 연결 누락 | 배관·신호 간선 삭제 | 재현율 |
| 거짓 연결 | 이웃 5개 안 요소 쌍에 간선 추가 | 정밀도 |
| 라벨 맞바꿈 | 선 라벨 교환 | 없음 |
| 분기점 분할 | 간선 중간에 연결 둘인 분기점 삽입 | 재현율·정밀도(위상) |
| 요소 병합 | 가까운 기호 쌍을 한 노드로 | 재현율 |
| 문자 오독 | 글자 혼동·끝 글자 누락·삽입 | 문자 복원율 |
| 요소 누락 | 기호·계기·노즐 노드 삭제 | 재현율, 문자 복원율 |
| 문자 귀속 | 번호·치수 토큰을 가장 가까운 같은 종류 요소로 이동 | 없음(근거 보존율만) |
| 복합 | 연결 누락 + 문자 오독 | 재현율, 문자 복원율 |

비율 10·20·30·50%, 씨앗 3개. 모든 설정에서 간선 재현율·정밀도, 문자 복원율, 근거 보존율을 실측함.

### 4.3 입력 조건과 모델

- 입력: ocr(기준선), relations(요소+연결), full(+장비 간 도달 사전 계산). 도달 집합은 오류가 들어간 그래프에서 다시 계산함
- 모델 사다리: 공개 가중치 8B(CPU, 폐쇄망 하한), 공개 가중치 14B, 상용 소형, 상용 중형. 14B와 상용 중형은 대표 설정(오류 없음, 누락·오독·귀속·복합 0.2·0.5, 거짓 0.5, 실제 2종)으로 씨앗 0, full만
- 재현 조건: 온도 0, 씨앗 고정, 순차 실행(동시 요청 시 출력이 달라짐을 확인)
- 통계: 씨앗 평균, 문항 재표집 구간, 오류 수준 간 대응 비교, 실물 12장은 도면 단위 구간

### 4.4 절차 계층 축(Q5, 코드)

- 이미 있는 실측: 상용 소형 연결 15문항은 relations 조건 7%, 장비 간 도달을 미리 계산해 넣은 full 조건 67%. 코드 한 조각의 효과
- 추가 조건: full에 경로(최단 경로의 중간 요소), 라인 경로(경로 위 라인 번호), 라인 도달(라인 번호에서 도달하는 장비)을 미리 계산한 줄을 더한 직렬화. 8B 연결 36문항의 바닥(22%)이 파인튜닝 없이 얼마나 오르는지 먼저 잼
- 같은 오류 설정에서 측정해, 사전 계산이 오류 전파를 막는지 키우는지도 봄(누락된 간선 위 경로는 사전 계산에서도 빠짐)
- 11-04 상용 소형 결과(연결 36문항, 대표 12설정, 씨앗 0): 오류 없는 그래프에서 full 44.4% → paths 88.9%(짝 비교 paths만 정답 16, full만 정답 0). 문자 귀속 오류에서도 94.4·83.3%로 이득 유지. 연결 누락·문자 오독·복합에서는 오류가 사전 계산에 전파되어 full과 비슷함(누락 0.5 30.6%, 복합 0.5 11.1%). 실제 추출 36.1·47.2%(full 17~31%, 유의하지 않음). 결론 형태: 코드는 추출이 맞을 때만 효과가 있고 잘못된 연결을 복구하지 못함. 88.9%는 코드와 모델을 합친 성능으로 표기

### 4.5 파인튜닝 축(Q5, 가중치, 조건부)

- 온톨로지: DEXPI 정보 모델(공개 표준). 회사 비공개 자료 없이 도면 온톨로지 기반 학습이 가능함
- 학습 자료: 정답 그래프에서 규칙으로 만든 직렬화 문맥과 질문·정답 쌍. 오류 주입기로 깨끗한 문맥과 오류 문맥을 모두 생성. 태그 무작위 치환으로 외우기 차단
- 분리: 학습은 PID2Graph Dataset PID 위상에 합성 문자를 붙인 그래프와 C02(태그 치환 사본 포함), 평가는 C01 기존 설정·문항과 실물 12장. C01은 학습에 넣지 않음. C03 벡터 추출 그래프는 문자가 거의 없어 제외. 구현 `examples/llm-qa/finetune/`
- 조건: 입력(원본 그래프, 사전 계산) × 가중치(기본, 파인튜닝) 2×2, 상용 중형을 기준선으로 둠. 학습 자료는 깨끗한 문맥과 오류 문맥 두 종
- 방법: 8B에 LoRA 지도 학습 1종. VRAM 12 GB 이상 GPU 필요(노트북 불가)
- 가설: 연결 추론(8B 22%)은 크게 오르고, 문자 오독·귀속 민감도는 남으며, 연결 누락은 복구되지 않음
- 판정: 1주 파일럿에서 C01 연결 문항(대표 설정 12개, 기본 가중치도 같은 HF 코드로 재측정)이 의미 있게 오르면 본 실험에 넣고, 아니면 Q1~Q4로 투고하고 후속 과제로 둠

## 7. 위험

- 도면 수: C01 1장 중심이라 실물 12장 반복이 없으면 일반성 주장이 약함
- 근거 보존율은 정답을 알아야 계산되므로 평가용 지표이며 운영 중 품질 추정에는 쓸 수 없음을 명시해야 함
- 모델 비교는 도면 1장·43문항·씨앗 1개 기준이라 구간 없이 단정하지 않음
- 파인튜닝은 GPU와 3~4주가 추가로 필요하므로 범위를 8B·LoRA 1종으로 제한함
