# multimodal-doc-structuring

비정형 데이터(표, 이미지, 기술문서)를 AI가 효율적으로 이해하고 활용할 수 있도록 하는 데이터 전처리와 구조화 방안. 폐쇄망과 제한된 연산 자원에서 기존 텍스트 LLM으로 운용하는 조건을 전제로 함.

## 현행 구상

[v5 기술 그림의 관계 그래프 기반 구조화 및 LLM 연계](docs/concept/v5-기하-요소-그래프-기반-기술-그림-구조화.md) (세부: [v5-상세](docs/concept/v5-상세.md))

- 문제: 기존 OCR과 RAG는 그림의 문자는 추출하나 연결, 위치, 지시 관계를 잃음
- 해결책: 기술 도면과 도식의 시각 요소를 추출해 요소 간 관계의 그래프로 구조화하고 질문 관련 부분 그래프를 텍스트로 기존 텍스트 LLM에 전달
- 경쟁 포인트: 요소 간 관계를 기존 텍스트 LLM이 활용할 수 있는 공통 구조로 변환
- 초기 범위: 문자, 기호, 연결 관계 복원. 치수와 형상 대응, 차트는 이후 확장. 사진과 렌더링은 이미지 검색에 한정
- 검증: OCR 기반 RAG와 관계 질의 정답률, 처리 시간, GPU 사용량 비교. 관계마다 원본 영역 추적
- 환경: 생성형 VLM 미사용, 기존 텍스트 LLM, 폐쇄망, 제한된 GPU
- 이전 안: `docs/concept/archive/`

## 예시와 검증

- [공개 참조 P&ID 한 장의 관계 그래프 변환](examples/dexpi-reference-pid/README.md). 선, 곡선, 타원, 문자만으로 장비 5, 계기 4, 밸브와 기호 19, 배관 구간 44개를 추출하고 정답 인접 쌍 27개를 모두 복원함. 질문별 부분 그래프를 텍스트로 직렬화해 기존 텍스트 LLM에 전달하는 형태까지 포함.
- [공개 도면 5장과 실제 문서 10쪽으로 확인한 추출 성능](examples/public-documents/README.md). 벡터 원본, 200 dpi 래스터, 스캔 열화의 세 조건에서 정답 대조. CPU 1대, 공개 OCR 모델과 영상 처리 규칙만 사용. 벡터 표준 도면은 전부 복원하나 래스터는 절반으로 떨어지며 원인과 시간을 기록함. 정비 지침서의 볼트 표(삽화·부품 번호·설명 행)와 치수·공차 도면의 지시선 추출 결과 포함.
- [질의응답 정답률 실험](examples/llm-qa/README.md). 공개 자료 15건에서 정답이 확정된 240문항을 만들고, 같은 모델에 문자 인식 텍스트·전체 직렬화·부분 그래프의 세 입력을 주어 정답률을 비교. 상용 소형 모델 39%·59%·58%(엄격 채점, 95% 구간 포함), 벡터 P&ID 16%→88%, 관계 질문에서 효과가 크고 표 질문은 문자 인식 텍스트가 높음. CPU로 실행한 8B급 공개 가중치 모델도 같은 크기의 효과(같은 80문항에서 36%·62%·64%). 질문 종류별 표현 선택(사후 규칙)으로 64~65%. 네 차례 직렬화·추출 개선의 누적 효과와 오답 유형 분석 포함.
- [논문 초고(국문)](docs/paper/논문-초고.md). 방법, 실험 설계, 결과, 분석, 한계를 정리한 초고.
- [한글 문서 OCR 측정](examples/korean-ocr/README.md). 합성 한글 기술 문서 1쪽을 200·150·100 dpi 스캔 열화로 읽어 문자 오류율 9~27%, 시간 7~26초를 기록. 탐지 해상도·배치·스레드 설정별 시간 비교 포함.

## 화면

- [문서 구조화 화면](app/README.md): `app/문서-구조화.html`을 열면 표본 20건(도면·도해·표·보고서·사진)의 입력 판별, 원본 위 겹층, 관계 그래프, 직렬화 텍스트, 색인, 표·본문, 질의, 자원 사용이 한 화면에 보임. 새 그림은 `python app/process.py <폴더>`로 처리해 같은 화면을 만듦. 코어·메모리에 맞춰 스레드·배치·입력 크기를 자동으로 정함
- [처리 과정 화면](app/README.md#처리-과정-화면): `app/문서-구조화-과정.html`을 열면 문서 종류별 대표 예시 8건의 처리 단계(판별, 문자, 선·도형, 표, 연결, 역할, 관계 그래프, 직렬화, 질의 부분 그래프)가 원본 위 겹층과 생성 자료 형태로 차례로 재생됨

## 작성 규칙

- 공개 저장소. 특정 조직의 내부 시스템, 모델, 인원, 운영 현황 기재 금지. 일반적인 폐쇄망과 공개 모델 환경으로 표현
- 문서는 한국어 문어체. 표와 제목은 명사형 또는 "-함"
- 구상안은 버전별 md로 관리하고 대체된 안은 `docs/concept/archive/`로 이동
- 실측과 합성 데이터 결과는 구분 표기. 통제 실험의 한계 명시
- 생성 데이터, 렌더 이미지, 캐시는 커밋하지 않음(`.gitignore`)
