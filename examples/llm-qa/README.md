# 질의응답 정답률 실험

구조화 결과가 텍스트 전용 LLM의 답에 얼마나 도움이 되는지 잰다. 같은 문서에 대해 세 가지 입력 조건으로 같은 질문을 하고 정답률을 비교함.

| 조건 | 입력 | 뜻 |
|---|---|---|
| `ocr` | 문자 인식 결과(벡터는 SVG 문자)를 읽는 순서로 이어 붙인 텍스트 | 구조화 없는 기준선 |
| `full` | 전체 직렬화(`graph.txt`·`page.txt`: 요소·연결·표·문단·관계) | 문서 한 장을 통째로 투입 |
| `retrieved` | 질문 태그 기준 2단계 부분 그래프와 질문어가 겹치는 줄(표 머리글 포함) | 검색 후 투입(RAG) |

## 자료와 정답

| 자료 | 문항 | 정답 출처 |
|---|---|---|
| DEXPI C01 P&ID: 벡터, 200 dpi 래스터, 스캔 열화 | 43 × 3 | DEXPI XML(연결·노즐 수·노즐 호칭 지름·라인 속성·계기 기능 문자) |
| DEXPI C02·C03 P&ID 벡터 | 12 | DEXPI XML |
| 합성 보고서(영문 PDF 글자 층·150 dpi 스캔), 한글 보고서, 한글 표·본문 스캔 | 35 | 생성 스크립트의 값 |
| 합성 기계 도면(벡터·래스터) | 20 | 생성 스크립트의 값 |
| FAA AC 43.13-1B 토크 표(원본·스캔), 볼트 표, 본문 2단 쪽 | 44 | 원문 대조 값 |

DEXPI 플랜트·실험실 도면(DP·DL)은 그림과 XML 모두에 문자 라벨이 없어 태그 기준 질문을 만들 수 없으므로 제외함.

연결 질문은 "장비 X에서 배관을 따라 다른 장비를 거치지 않고 바로 도달하는 장비 태그"이며 정답은 XML 연결 정보에서 이름 없는 부품(밸브 등)을 지나 탐색해 만든 집합임. 채점은 2026-10-30 저녁에 엄격한 규칙으로 바꿈: 근거 없음 취지의 응답('자료에 없음', '확인되지 않음' 등)은 정답 숫자가 섞여 있어도 오답, 숫자 답은 자릿수 경계가 맞는 숫자 토큰만 인정(80과 800 구분), 문자 답은 낱말 경계 안의 포함(영문 복수형 허용), 집합 답은 응답에서 뽑은 태그 집합의 완전 일치(질문에 든 기준 태그 제외). 아래 수치는 모두 이 규칙으로 다시 채점한 값이며, 이전 포함 여부 규칙으로는 4차 full이 62.5%였음(차이 3.7%p, 오채점 20건은 모두 ocr·full 조건의 정답→오답).

## 실행

```
python prepare_docs.py          # C02·C03 벡터 도면 처리(표본 결과는 examples/sample-inputs/output 사용)
python make_questions.py        # questions.json
python contexts.py              # contexts.json(세 조건 문맥)
python run_qa.py --backend api --model <모델 id> --label <결과 이름>   # OpenAI 호환 API, 환경 변수 LLM_API_BASE·LLM_API_KEY
python run_qa.py --backend ollama --model <모델 이름>        # 공개 가중치 모델, 로컬 Ollama
python run_qa.py --backend ollama --model <모델 이름> --ids subset-80.json --label open-8b-2026-10-s80   # CPU 실행 시간이 길 때 층화 80문항(자료 묶음×질문 종류 비율 유지, 씨앗 0)
bash run_open_models.sh [모델 ...]  # 공개 가중치 비교군(8B·7B·14B급) 일괄 실행, 결과 이름 open-<규모>-<연월>
python analyze.py <결과 이름>   # results/<결과 이름>-analysis.md: 신뢰구간, 조건 간 대응 비교, 종류별 정답률, 오답 유형
```

결과는 `results/<결과 이름>.jsonl`(문항·조건별 응답)과 `results/<결과 이름>.md`(자료별·질문 종류별 정답률, 입력 길이, 응답 시간). 중단 후 다시 실행하면 남은 문항만 호출함. 결과 이름에는 공급사·모델명을 쓰지 않고 규모와 시점만 적음.

240문항은 서로 다른 질문 문장 121개를 원본·래스터·스캔 자료에 반복한 것이므로 문항이 독립이 아님. 질문 문장을 묶음으로 재표집한 구간을 함께 씀. 같은 문항의 대응 비교에서 full은 ocr보다 65문항을 더 맞추고 18문항을 놓침(차이의 95% 구간 [+12.9, +26.2]%p). full과 retrieved의 차이는 [-5.0, +3.3]%p로 구간이 0을 포함함. 질문 종류별(ocr/full/retrieved)로는 연결 0/67/47%, 개수 0/62/62%, 노즐 7/52/62%, 라인 22/43/49%, 계기 23/62/38%로 관계 질문에서 full이 ocr보다 21~67%p 높고, 표 87/68/62%, 치수 67/42/42%, 그림 75/50/50%로 읽기 질문은 ocr이 높음. 오답의 대부분은 '자료에 없음'(ocr 110, full 61)이며 full 조건에서 그중 38건은 래스터 P&ID임.

질문 종류별 표현 선택(사후 규칙): 관계 질문(연결·개수·노즐·라인·계기)에는 그래프 조건, 읽기 질문(표·본문·치수·그림·주석)에는 문자 인식 텍스트를 쓰면 같은 응답에서 64.2%(full)·65.0%(retrieved)가 됨. 규칙을 결과를 본 뒤 정했으므로 상한에 가까운 추정이며 별도 평가 세트에서 다시 재야 함.

### 공개 가중치 모델 비교군

폐쇄망·CPU 전용 조건을 흉내 내어 8B급 공개 가중치 지시 모델을 노트북 CPU(16코어, GPU 가속 없음)에서 로컬 실행함(`open-8b-2026-10-s80`). 호출당 30~110초가 걸려 층화 80문항(`subset-80.json`, 자료 묶음×질문 종류 비율 유지)으로 줄였고, 같은 80문항에서 상용 소형 모델(4차)의 값을 다시 계산해 나란히 둠.

| 모델 | 문항 | ocr | full | retrieved |
|---|---|---|---|---|
| 상용 API 소형(4차, 같은 80문항) | 80 | 36% | 57% | 61% |
| 공개 가중치 8B(CPU) | 80 | 36% [25, 46] | 62% [51, 72] | 64% [54, 74] |
| 공개 가중치 8B(CPU), 전체 문항 | 240 | 38% (90/240) | 65% (156/240) | - |

2026-10-31에 같은 모델로 남은 160문항을 ocr·full 두 조건에서 마저 실행해 240문항 전체 값을 얻음(`open-8b-2026-10-all`, 80문항 결과를 이어서 사용). 같은 240문항의 상용 소형 모델(4차)은 ocr 39%, full 59%. 공개 가중치 8B의 개선 폭은 +27.5%p(80문항 +26.3%p)로 표본을 늘려도 같은 크기임. 자료별로는 P&ID에서 개선이 크고(C01 벡터 28→91%, 래스터·스캔 7→47~49%), 표·본문·보고서 쪽은 OCR과 같거나 낮음.

두 모델의 조건별 정답률이 0~5%p 안에서 같음. 구조화 직렬화의 효과가 특정 모델에 매여 있지 않고, 공개 가중치 8B 모델을 CPU에서 돌리는 폐쇄망 조건에서도 같은 크기로 나타남. 질문 종류별로도 같은 모양(연결 0→50~83%, 노즐 10→65~75%, 표는 ocr이 같거나 높음)임. 응답 시간은 Ollama의 프롬프트 캐시 순서 효과가 있어 조건 간 비교에 쓰지 않음. 7B·14B급은 시간 제약으로 실행하지 않음.

해석:
- 관계 그래프 직렬화의 효과는 벡터 P&ID에서 분명함(C01 16% → 88%, C02·C03 25% → 58%). 연결 질문은 모델이 배관·분기점을 여러 단계 따라가지 못해 1차 7%였고, 구조화 단계에서 장비 간 도달을 미리 계산해 넣자 4차 67%가 됨.
- 래스터 P&ID는 추출 품질이 상한임. 조각·눈금 병합과 모서리 연결로 정답 인접 쌍이 12/27에서 18/27(200 dpi), 16/27(스캔)로 오르자 full 정답률이 21% → 33%(200 dpi), 16% → 37%(스캔)로 오름. 남은 오답은 태그 문자 인식 오류(H1008을 S8로)와 복원되지 않은 연결임.
- 표·본문 쪽은 문자 인식 결과로 70~100%라 구조화 이득이 없음. 4차의 표 머리글=값 직렬화는 FAA 토크 표에서 full을 54%로 떨어뜨렸고(ocr 89%), 기계 도면 래스터도 20%임. 직렬화의 좌표·관계 줄과 머리글 반복이 소형 모델의 표 읽기를 방해하므로 표 질의에는 문자 인식 텍스트나 행 단위 표 형식을 쓰는 편이 나음. 질문 종류에 따른 표현 선택이 다음 단계임.
- 부분 그래프 조건은 입력 길이가 전체 직렬화의 28%(2,274자 대 8,006자)이면서 정답률 차이는 1%p이고 구간이 0을 포함함.

한계: 세 조건 모두 질문이 속한 문서 1건의 자료를 넣는 실험이며, 여러 문서에서 조각을 찾아오는 검색(어휘·임베딩)은 측정하지 않음. retrieved 조건의 검색은 태그 기준 그래프 탐색과 질문어 겹침임. 같은 240문항으로 직렬화를 네 차례 고쳤으므로 문항이 개선에 쓰인 셈이며, 별도의 미사용 평가 세트가 없음. 정답 복원은 작성 양식이 같은 DEXPI C01에서 가장 높고(27/27), 양식이 다른 C02·C03(3/6, 4/9)과 복잡한 플랜트 도면(84/157)에서는 떨어짐.
