# 질의응답 정답률 실험

구조화 결과가 텍스트 전용 LLM의 답에 얼마나 도움이 되는지 잰다. 같은 문서에 대해 세 가지 입력 조건으로 같은 질문을 하고 정답률을 비교함.

| 조건 | 입력 | 뜻 |
|---|---|---|
| `ocr` | 문자 인식 결과(벡터는 SVG 문자)를 읽는 순서로 이어 붙인 텍스트 | 구조화 없는 기준선 |
| `full` | 전체 직렬화(`graph.txt`·`page.txt`: 요소·연결·표·문단·관계) | 문서 한 장을 통째로 투입 |
| `retrieved` | 질문 태그 기준 2단계 부분 그래프와 질문어가 겹치는 줄(표 머리글 포함) | 검색 후 투입(RAG) |

### 2026-11-02 변경: 검색 정답 누출 수정과 조건 분리

- 이전 `retrieved` 조건은 문항 파일의 `focus` 필드로 부분 그래프를 찾았음. 240문항 중 25문항은 `focus`가 정답 문자열과 같고(계기 기능 문자 등) 34문항은 `focus`가 질문 문장에 없어 실제 사용 조건보다 유리했음. 이제 질문 문장에 그대로 적힌 그래프 요소 이름을 검색 기준으로 씀(`contexts.question_keys`). 이전 `retrieved` 결과는 비교에서 제외함. `ocr`·`full`은 `focus`를 쓰지 않아 영향 없음
- 계기 질문의 예시 문자 "(예: PI, TIC)"에 정답 PI가 들어 있어 "(예: FIC, LT)"로 바꿈(자료에 없는 문자). 해당 13문항은 전 조건 재실행 필요
- 관계 정보의 효과를 분리하는 조건 추가. 같은 추출 결과에서 줄을 빼서 만듦

| 조건 | 입력 | 비교로 보는 것 |
|---|---|---|
| `objects` | 요소·속성 목록(요소, 표, 기타 문자, 선 라벨). 분기점·연결·장비 간 도달 제외, 쪽·도해는 관계·지시선 제외 | ocr 대비: 정보 정리의 효과 |
| `relations` | objects + 분기점·연결 | objects 대비: 관계 정보의 효과 |
| `full` | relations + 장비 간 배관 연결(도달 집합) | relations 대비: 그래프 탐색을 전처리에서 수행한 효과 |
| `both` | ocr + full | 질문별 선택 규칙의 보조 조건 |

- 질문별 표현 선택(`select_repr.py`): 질문 문장과 입력 판별 결과를 입력으로 쓰는 규칙. 도면 경로이고 관계 단서 어휘가 있으면 full, 도면 경로이고 단서가 없으면 both, 쪽·도해 경로면 ocr. 규칙은 현재 240문항(개발 세트)에서 확정하고 미사용 평가 세트에 그대로 적용함. 기존 응답으로 계산한 개발 세트 값: 8B 공개 가중치 66.2%(full 고정 65.0%, ocr 37.5%, 평균 입력 6,079자 대 8,006자), 상용 소형 64.2%(full 58.8%)
- 노트북 실행: `bash run_ablation.sh llama3.1:8b`. 이전 결과에서 질문·문맥이 같은 ocr·full 응답 454건을 옮기고 남은 호출(약 750회)을 실행함

- 11-03 상용 소형 결과(`api-small-2026-11-noise2`, `-conn2`): 연결 누락은 86→64%로 비율에 따라 떨어지고 거짓 연결은 86→78%, 라벨 맞바꿈·분기점 분할·요소 병합은 80~88%로 변화 없음. 같은 도면의 실제 추출(200 dpi·스캔, 재현율 0.71~0.73)은 28~37%로 같은 재현율의 통제 오류(67~71%)보다 훨씬 낮음. 차이는 연결이 아니라 요소 문자(태그) 쪽 손실로 보아 문자 오독 오류 `ocr`을 추가함. 연결 의존 36문항은 오류 없는 그래프에서도 44%이며 도달 여부 10/10, 연결 수 3/5, 경로 중간 요소 수 0/5, 라인 경로 1/5, 라인 도달 2/11임. 소형 모델이 다단계 경로를 스스로 따라가지 못하므로 민감도 분석에는 도달 여부·연결 수를 쓰고 나머지는 전처리에서 미리 계산해야 하는 정보의 근거로 씀
- `ocr` 오류: 요소·선 문자 토큰의 비율 p를 글자 혼동(8→B, 5→S, 0→D, 1→l 등)·끝 글자 누락·글자 삽입으로 바꿈. 실측 지표로 요소 문자 복원율(정답 XML의 식별자 문자 72개 중 그래프 토큰에 그대로 있는 비율, 기준 0.88, 실제 200 dpi 0.82, 스캔 0.72)을 `noise/graphs.md`에 함께 기록함. 같은 결과 이름으로 다시 실행하면 새 설정만 추가로 묻음
- `diagnose_real.py <결과 이름> --settings ^real`: 오답을 문맥과 대조해 기준 문자 손실·답 문자 손실·귀속 오류·연결 오류·모델 오류로 자동 분류(results/<결과 이름>-diagnose.md). 실제 추출의 하락을 오류 축별로 분해하는 용도
- 실제 추출 오답 분류(상용 소형, full, `api-small-2026-11-noise2-diagnose.md`): 200 dpi 오답 31개 = 기준 문자 손실 15, 답 문자 손실 2, 귀속 오류(노즐 번호와 호칭 지름의 짝 없음 등) 10, 연결 오류 2, 모델 오류 2. 스캔 오답 27개 = 15, 2, 7, 1, 2. 실제 추출의 손실은 문자 복원(55%)과 문자 귀속(32%)이 거의 전부이고 연결 오류는 6%임. 통제 오류 문자 오독 20~30%도 같은 구성(기준 문자 손실 12~16)이라 실제 추출이 놓이는 곡선이 문자 오독 축임을 뒷받침함
- `mix` 오류: 연결 누락과 문자 오독을 같은 비율로 함께 넣음(문자 오독의 난수 씨앗은 단일 설정과 다름). 두 효과가 독립이면 정답률이 두 단일 곡선의 곱 근처에 놓임. mix의 문자 복원율이 같은 비율의 ocr보다 0.01~0.04 낮은 것은 지운 선에 붙어 있던 노즐 문자(N8, 800 등)가 함께 사라지는 것과 난수 표본 차이 때문이며, 비교는 실측 문자 복원율 기준으로 함. 상용 소형 결과: 10/20/30/50%에서 46.5/40.3/32.6/13.2%로 독립 가정 예측(54/42/37/21%)보다 2~8%p 낮음. 연결 문항은 drop 0.1 5/15, ocr 0.1 11/15인데 mix 0.1은 1/15
- `node` 오류: 기호·계기·노즐 노드의 비율 p를 지우고 붙은 선도 끊음(실제 래스터에서 작은 기호를 못 찾는 오류). 상용 소형 결과에서 실제 추출의 정답률 하락이 노즐 문항(통제 51/54 대 실제 3~8/18)에 몰려 있어 문자 오독과 요소 누락 두 축으로 실제 오류를 분해함
- `attr` 오류: 요소에 붙은 번호·치수 토큰(노즐 호칭 지름, 계기 번호, 밸브 번호)의 비율 p를 가장 가까운 같은 종류 요소로 옮김(문자 귀속 오류). 문자는 문맥에 남으므로 문자 복원율은 0.88 그대로이고, 간선 재현율·정밀도도 1.00이라 기존 지표로는 오류 없는 그래프와 구별되지 않음. 실제 추출 오답의 32%를 차지하는 귀속 오류를 단독으로 재는 설정
- `evidence.py --label <결과 이름>`: 설정마다 43문항의 근거가 문맥에 남아 있는지를 `diagnose_real.classify`로 판정해 기준 보존율·답 보존율·근거 보존율(정답 문자가 기준 요소 줄에 있음, 연결 문항은 도달 집합 일치)을 구하고, 정답률을 근거 있는 문항과 없는 문항으로 나눔. 설정 단위로 정답률과 지표의 상관도 냄(results/<결과 이름>-evidence.md). 오류 없는 기준 그래프에서도 T4750 노즐 2문항은 근거가 없어 상한이 0.95임
- 근거 보존율 결과(상용 소형 `api-small-2026-11-noise2-evidence.md`, 설정 39개): 정답률과의 피어슨 상관이 배관 연결 재현율 0.23, 정밀도 0.01, 문자 복원율 0.84, 근거 보존율 0.99(스피어만 0.93). 근거가 남은 문항의 정답률은 오류 종류·비율과 무관하게 75~95%(오류 없음 90%)이고 근거가 없는 문항은 0~33%라 정답률 ≈ 근거 보존율 × 0.9로 설명됨. 8B(`open-8b-2026-11-noise`, 완료된 설정 21개)도 근거 있음 80~88%로 같음. 그래프 품질 지표로는 간선 재현율·정밀도가 아니라 질문 대상 문자의 복원과 귀속을 재야 한다는 근거
- 11-04 attr 결과(상용 소형, full): 10/20/30/50%에서 76.7/71.3/56.6/46.5%. 간선 재현율·정밀도 1.00, 문자 복원율 0.88이 그대로인데 정답률은 최대 40%p 떨어짐. 하락은 노즐(51→17/54)·개수(12→3/15)·계기 문항에 몰리고 라인 문항은 변화 없음(선 라벨은 옮기지 않음). 연결 의존 36문항은 44→40%로 변화 없음. 근거 보존율 0.84/0.74/0.67/0.60과 같은 추세이며, 비율 30% 이상에서는 근거가 남은 문항도 75~83%로 내려감(한 요소 줄에 번호가 중복돼 모델이 헷갈림). 실제 추출의 노즐 문항(3/18, 8/18)은 ocr·attr 곡선 범위 안에 들어옴
- 11-04 절차 계층 조건 `paths`(`precompute.py`): full 문맥에 코드로 미리 계산한 연결 정보 줄(장비별 연결선 수, 이어진 장비 쌍의 최단 경로 중간 요소 수와 경로 위 라인 번호, 라인 번호에서 도달하는 장비)을 덧붙임. 연결 의존 문항 36개가 묻는 것과 같은 계산이며 `make_conn_questions.py`도 같은 함수를 씀. 오류가 든 그래프에서는 미리 계산한 줄에도 오류가 전파됨. 모델이 연결을 스스로 따라가지 못해 생기는 바닥(8B 연결 문항 22%, 상용 소형 44%)이 코드로 얼마나 풀리는지, 그리고 파인튜닝과 어느 쪽이 더 기여하는지를 비교하는 용도. 실행: `run_noise.py --conds paths`

연결 질문은 "장비 X에서 배관을 따라 다른 장비를 거치지 않고 바로 도달하는 장비 태그"이며 정답은 XML 연결 정보에서 이름 없는 부품(밸브 등)을 지나 탐색해 만든 집합임. 채점은 2026-10-30 저녁에 엄격한 규칙으로 바꿈: 근거 없음 취지의 응답('자료에 없음', '확인되지 않음' 등)은 정답 숫자가 섞여 있어도 오답, 숫자 답은 자릿수 경계가 맞는 숫자 토큰만 인정(80과 800 구분), 문자 답은 낱말 경계 안의 포함(영문 복수형 허용), 집합 답은 응답에서 뽑은 태그 집합의 완전 일치(질문에 든 기준 태그 제외). 아래 수치는 모두 이 규칙으로 다시 채점한 값이며, 이전 포함 여부 규칙으로는 4차 full이 62.5%였음(차이 3.7%p, 오채점 20건은 모두 ocr·full 조건의 정답→오답).

### 공개 가중치 모델 비교군

폐쇄망·CPU 전용 조건을 흉내 내어 8B급 공개 가중치 지시 모델을 노트북 CPU(16코어, GPU 가속 없음)에서 로컬 실행함(`open-8b-2026-10-s80`). 호출당 30~110초가 걸려 층화 80문항(`subset-80.json`, 자료 묶음×질문 종류 비율 유지)으로 줄였고, 같은 80문항에서 상용 소형 모델(4차)의 값을 다시 계산해 나란히 둠.

| 모델 | 문항 | ocr | full | retrieved |
|---|---|---|---|---|
| 상용 API 소형(4차, 같은 80문항) | 80 | 36% | 57% | 61% |
| 공개 가중치 8B(CPU) | 80 | 36% [25, 46] | 62% [51, 72] | 64% [54, 74] |
| 공개 가중치 8B(CPU), 전체 문항 | 240 | 38% (90/240) | 65% (156/240) | - |

2026-10-31에 같은 모델로 남은 160문항을 ocr·full 두 조건에서 마저 실행해 240문항 전체 값을 얻음(`open-8b-2026-10-all`, 80문항 결과를 이어서 사용). 같은 240문항의 상용 소형 모델(4차)은 ocr 39%, full 59%. 공개 가중치 8B의 개선 폭은 +27.5%p(80문항 +26.3%p)로 표본을 늘려도 같은 크기임. 자료별로는 P&ID에서 개선이 크고(C01 벡터 28→91%, 래스터·스캔 7→47~49%), 표·본문·보고서 쪽은 OCR과 같거나 낮음.

두 모델의 조건별 정답률이 0~5%p 안에서 같음. 구조화 직렬화의 효과가 특정 모델에 매여 있지 않고, 공개 가중치 8B 모델을 CPU에서 돌리는 폐쇄망 조건에서도 같은 크기로 나타남. 질문 종류별로도 같은 모양(연결 0→50~83%, 노즐 10→65~75%, 표는 ocr이 같거나 높음)임. 응답 시간은 Ollama의 프롬프트 캐시 순서 효과가 있어 조건 간 비교에 쓰지 않음. 7B·14B급은 시간 제약으로 실행하지 않음.

해석:
- 관계 그래프 직렬화의 효과는 벡터 P&ID에서 분명함(C01 16% → 88%, C02·C03 25% → 58%). 연결 질문은 모델이 배관·분기점을 여러 단계 따라가지 못해 1차 7%였고, 구조화 단계에서 장비 간 도달을 미리 계산해 넣자 4차 67%가 됨.
- 래스터 P&ID는 추출 품질이 상한임. 조각·눈금 병합과 모서리 연결로 정답 인접 쌍이 12/27에서 18/27(200 dpi), 16/27(스캔)로 오르자 full 정답률이 21% → 33%(200 dpi), 16% → 37%(스캔)로 오름. 남은 오답은 태그 문자 인식 오류(H1008을 S8로)와 복원되지 않은 연결임.
- 표·본문 쪽은 문자 인식 결과로 70~100%라 구조화 이득이 없음. 4차의 표 머리글=값 직렬화는 FAA 토크 표에서 full을 54%로 떨어뜨렸고(ocr 89%), 기계 도면 래스터도 20%임. 직렬화의 좌표·관계 줄과 머리글 반복이 소형 모델의 표 읽기를 방해하므로 표 질의에는 문자 인식 텍스트나 행 단위 표 형식을 쓰는 편이 나음. 질문 종류에 따른 표현 선택이 다음 단계임.
- 부분 그래프 조건은 입력 길이가 전체 직렬화의 28%(2,274자 대 8,006자)이면서 정답률 차이는 1%p이고 구간이 0을 포함함.
