# 한글 문서 OCR 측정

합성 한글 기술 문서 1쪽(제목, 본문 3문단, 표 6행 4열, 주, 468자)을 300 dpi로 그린 뒤 200·150·100 dpi로 줄이고 스캔 열화(0.4도 회전, 흐림, 잡음, JPEG 50)를 더해 CPU OCR(공개 가중치, 한글·영어)로 읽음. 정답은 그릴 때 기록한 문자열. 실제 문서가 아닌 합성 자료임.

## 결과 (4코어 CPU, 스레드 4, 인식 배치 8)

| 조건 | 문자 오류율(CER) | 숫자·부품 번호 22개 중 정확 | 평균 신뢰도 | 시간 |
|---|---|---|---|---|
| 200 dpi 원본 | 9.0% | 19 | 0.71 | 41.5초(첫 실행, 모델 적재 포함) |
| 200 dpi 스캔 열화 | 10.0% | 17 | 0.74 | 25.5초 |
| 150 dpi 스캔 열화 | 11.5% | 14 | 0.70 | 11.5초 |
| 100 dpi 스캔 열화 | 26.5% | 5 | 0.57 | 7.1초 |

오류 유형: 받침·유사 자모 혼동(사항→사랑, 볼트→불트, 한다→하다, 측정→축정), 문장 부호 탈락. 영문 부품 번호(AN3-5A, NAS6204-10, MS20365-428)는 200 dpi에서 대체로 정확하고 100 dpi에서 무너짐(AN4-7A→ANA-TA).

## 속도 설정 비교 (200 dpi 스캔 열화)

| 설정 | 시간 | CER |
|---|---|---|
| 기본(탐지·인식 모두 원본 해상도, 배치 8, 스레드 4) | 25.5초 | 10.0% |
| 탐지만 절반 해상도, 인식은 원본 상자 영역 | 6.4초 | 9.8% |
| 인식 배치 32 | 21.0초 | 10.0% |
| 스레드 1 | 53.2초 | 10.0% |

문자 탐지가 시간의 대부분을 차지하며 탐지 해상도를 절반으로 낮춰도 정확도가 유지됨. 화면 서버(`app/`)는 이 설정을 기본으로 씀.

## 파일

| 파일 | 내용 |
|---|---|
| `make_page.py` | 합성 쪽 생성과 열화 변형 |
| `run_ocr.py` | 변형별 OCR, CER·토큰 정확도·시간 측정, 설정 비교 |
| `output/page300.png`, `scan200.jpg`, `scan100.jpg` | 입력 표본 |
| `output/gt.json` | 정답 문자열과 상자 |
| `output/*_ocr.json` | 조건별 인식 결과(읽기 순서) |
| `output/results.json` | 측정치 |
