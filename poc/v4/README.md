# PoC v4 체결 토크 사례 (2026-10-28, 1차 실행)

구상안 v10의 처리 흐름을 합성 정비 문서로 실행하고 고정 길이 분할 방식과 비교함.

## 합성 문서

- 20건(디지털 10, 스캔본 10). 문서 1건 = 범위 조항 + 그림 1 조립도(부품 상자 4개, 원 안 번호 체결부 8개) + 표 1 체결부 토크(항목, 규격, 토크) + 각주(윤활 시 규격별 값) + 주기.
- 체결부와 부품의 소속은 그림에만, 토크 값은 표에만, 윤활 조건 값은 각주에만 있음.
- 스캔본은 130dpi 렌더 후 잡음, 흐림, JPEG 압축. 텍스트 레이어 없음.
- 생성: `python3 gen.py data`. 실행: `python3 pipeline.py data`. 생성 데이터는 커밋하지 않음.

## 실험군

| 실험군 | 전처리 | 입력 구성 |
|---|---|---|
| A 고정 분할 | pdftotext 또는 전체 페이지 300dpi OCR | 300토큰 청크, BM25 상위 3개 |
| B 평문 분할 | 제안과 같은 추출과 재처리 결과를 평문으로 펼침 | 300토큰 청크, BM25 상위 3개 |
| C 제안 | 전체 기본 추출(디지털 파서 또는 130dpi OCR과 도형 검출), 관계 점검, 문제 영역 300dpi 재처리, 구조화 | 질문의 대상과 조건에 맞는 관계만 |

관계 점검 기준: 그림의 체결부 수와 표의 행 수 불일치, 각주는 있는데 기호가 붙은 셀 없음, 체결부 번호 판독 실패 또는 중복.

컨테이너에는 VLM과 LLM이 없음. 추가 분석은 고해상도 영역 OCR로 대신하고 답변 판독은 규칙으로 함. A와 B의 수치는 입력에 정답 도출에 필요한 정보가 모두 있는 비율(근거 완전성).

## 결과

| 질의 유형 | 건수 | A | B | C | A 토큰 | B 토큰 | C 토큰 |
|---|---|---|---|---|---|---|---|
| 값 조회 | 160 | 50% | 91% | 97% | 236 | 368 | 44 |
| 조건 포함 조회 | 160 | 50% | 83% | 90% | 236 | 368 | 46 |
| 그림 연결 조회 | 28 | 0% | 0% | 86% | 273 | 369 | 65 |
| 조건 미지정 조회 | 28 | 0% | 0% | 86% | 273 | 369 | 84 |

- 디지털: A 84%, B 84%, C 100%. 스캔본: A 0%, B 63%, C 84%.
- C의 오답 29건 = 보류 24건(필요한 값이 미확정이라 전달하지 않음) + 오답 5건(규격 셀 미판독으로 건식 값만 전달 4건, 48을 43으로 오판독 1건).
- 스캔본 문서당 추가 분석 영역 평균 5.6개(체결부 번호 36회, 표 10회), 미해결 연결 평균 1.5건.
- 처리 시간(CPU): 스캔본 문서당 A 1.6초, C 기본 추출 2.9초 + 관계 점검과 재처리 4.4초. OCR 기준 재처리는 전체 페이지 고해상도 OCR보다 길었음.

## 확인된 한계와 반영

| 발견 | 반영 |
|---|---|
| 기본 해상도 OCR은 격자 표의 행과 원 안의 번호 1, 7을 자주 놓침 | 관계 점검 기준에 행 수와 체결부 수 불일치, 번호 판독 실패와 중복을 추가. 문제 영역만 고해상도 재처리 |
| 전체 페이지 OCR(psm 6)은 격자 표를 거의 읽지 못함 | 표 영역은 선 검출 후 셀 단위 OCR. 셀 높이 정규화와 이진화 필요 |
| 각주 기호 *는 작아서 셀에서 자주 누락 | 각주가 규격을 명시하므로 규격 기준으로 연결. 기호는 보조 근거 |
| OCR이 AI-330을 Al-330으로 읽음 | 식별자 정규화(l을 I로) 뒤 대조 |
| 원 안의 숫자는 이진화와 여백 없이는 판독률이 낮음 | 영역 재처리 시 이진화, 여백 추가, 단일 문자 모드 |
| 숫자 오판독(48을 43)은 관계 점검으로 발견되지 않음 | 원본 표본 대조와 중요 값 별도 확인 필요. 구상안 한계로 명시 |
| OCR 재처리는 비용이 줄지 않음 | 절감 조건을 VLM 기준으로 한정. 노트북에서 VLM 처리 시간 측정 |
