# PoC v4 계획 (v7 구상안 기준, 착수 전)

목적: v7의 사례(부품 위치도·운용 기준 표·각주의 연결)를 합성 기술문서로 재현하고, 실험군 A·B·C의 지표 4개를 측정함. 1장에는 사례 1건과 측정치를 표시함.

## 합성 문서

- 문서 1건 = 범위 조항 + 부품 위치도(객체 번호 주석) + 운용 기준 표(다단 헤더, 각주 표시 `*`) + 각주("정상 운전 시 적용", "비상 시 60초 이내") + 주기.
- 같은 계통의 두 구성(A·B)이 다른 값을 가짐. 각주 조건을 놓치면 다른 구성의 값을 고르게 됨.
- 절반은 스캔본(잡음·압축, 텍스트 레이어 없음). 생성기는 poc/v3/gen.py를 확장(각주 조건, 이미지 객체 주석, 지시선).
- 정답: 대상·속성·값·단위·조건·출처(표 셀 좌표, 이미지 객체 좌표, 각주 번호).

## 질의

| 유형 | 예 | 정답 판정 |
|---|---|---|
| 값 조회 | A-17의 정상 운전 허용 온도 | 값·단위 일치 |
| 조건 포함 조회 | A-17의 허용 온도와 적용 조건 | 값과 조건 모두 일치 |
| 이미지 연결 | 위치도에서 3번으로 표시된 부품의 허용 온도 | 이미지 객체→대상→값 연결 |
| 설명 | 비상 한계의 지속 가능 시간 | 각주 문구 일치 |

## 실험군

| 실험군 | 전처리 | 구조화·입력 | 실행 위치 |
|---|---|---|---|
| A | 일반 OCR(tesseract) | 고정 길이 텍스트 청크, 키워드 검색 상위 k | 컨테이너 |
| B | 문서 구조 인식(Docling 기본 파이프라인) | 표·문단 단위 구조 보존 청크 | 노트북(CPU, 가중치 보유) |
| C | 텍스트 레이어 직접 파싱 + 스캔본은 영역별 문서 VLM(Granite-Docling) | 대상·값·조건·출처 연결, 질문에 필요한 값과 근거로 입력 구성 | 파싱은 컨테이너, VLM은 노트북 |

동일 LLM(로컬 소형 모델, 노트북 CPU 또는 판정 규칙), 동일 질의, 동일 문서.

## 지표

| 지표 | 산출 |
|---|---|
| 정보 추출 정확도 | 표 셀 값 일치율 |
| 조건·관계 보존 정확도 | 값에 조건·이미지 객체·출처가 올바르게 연결된 비율 |
| 최종 QA 정답률 | 질의 유형별 정답률 |
| 질의당 처리 비용 | 입력 토큰(tiktoken), 질의당 이미지 처리 횟수 |

## 주의

- 합성 데이터 결과임을 1장에 명시.
- 기존 방식(A)이 각주를 올바르게 읽는 경우도 그대로 기록. 틀린다고 전제하지 않음.
- 구조화로 정확도가 낮아지는 유형이 있으면 기록.
- 생성 데이터·렌더 이미지는 커밋하지 않음(.gitignore).
