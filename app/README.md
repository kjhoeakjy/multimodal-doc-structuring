# 문서 구조화 화면

그림 파일 한 장을 넣으면 입력 종류 판별, 요소 추출, 관계 그래프, 직렬화 텍스트, 색인, 이미지 임베딩, 자원 사용까지 한 화면에 보이는 로컬 도구. `examples/public-documents`의 추출 코드를 그대로 호출함. 사용자가 고르는 설정은 없음.

## 실행

```
pip install -r app/requirements.txt
python app/server.py            # http://127.0.0.1:8765
```

첫 실행 시 OCR 가중치(한글·영어)를 내려받음. 폐쇄망에서는 가중치 파일을 미리 `~/.EasyOCR/model/`에 둠. 이미지 임베딩 가중치가 없으면 그 항목은 "모델 없음"으로 표시되고 나머지는 동작함.

## 처리 흐름

| 단계 | 내용 | 코드 |
|---|---|---|
| 입력 판별 | SVG·PDF 벡터는 벡터 경로. 래스터는 연속 계조 비율로 사진을, 격자 영역과 격자 밖 긴 선 수로 도면과 표·본문 쪽을 가름. 해상도는 파일 메타데이터, 없으면 A4 짧은 변 210 mm 가정 | `pipeline.classify_raster` |
| 도면 | 문자 인식, 긴 선, 닫힌 도형, 기호, 틀·표 제거, 연결 판정, 문자 부착, 역할 추정 | `examples/public-documents/pid/raster_graph.py`, `extract_graph.py` |
| 표·본문 쪽 | 격자선으로 칸을 나누고 문자를 칸에 배정, 표 밖 잉크 덩어리를 그림 영역으로 행에 연결, 표 밖 문자를 줄·문단으로 묶음 | `examples/public-documents/pages/real_docs.py`, `pipeline.paragraphs` |
| 사진 | 구조 추출 없음. 사진 위 문자와 이미지 임베딩 | `pipeline.Job.photo` |
| 직렬화 | 노드·간선·좌표(또는 표 행·문단)를 텍스트 LLM 입력용 줄 단위 텍스트로 | `pid/serialize.py` |
| 색인 | 완전 일치 키(태그·부품 번호), BM25용 토큰 통계, 표 행, 이미지 임베딩(쪽·그림 영역) | `pipeline.build_index`, `embed_images` |
| 질의 | 태그에서 n단계 부분 그래프와 근거 좌표 | `pipeline.subgraph` |

## 자원 제어

| 항목 | 규칙 |
|---|---|
| 스레드 | 코어 수의 절반. 다른 작업의 CPU 사용률이 50%를 넘으면 다시 절반 |
| 인식 배치 | 가용 메모리 2 GB 미만 1, 4 GB 미만 2, 8 GB 미만 4, 그 이상 8 |
| 입력 크기 | 가용 메모리에 따라 2·4·8·12 MP 상한. 넘으면 축소하고 해상도 값을 함께 조정 |
| 문자 탐지 | 원본 해상도 고정(정확도 우선) |
| 동시 처리 | 작업 대기열, 한 번에 하나 |
| 감시 | 처리 중 0.5초마다 메모리를 읽어 가용 0.5 GB 아래로 내려가면 경고 표시 |

설정과 근거는 화면의 요약 탭과 상단 표시줄에 그대로 나옴.

## 화면

왼쪽은 원본 위 겹층(문자, 장비·계기·기호, 배관·신호선, 분기점, 표, 그림 영역, 문단). 오른쪽은 요약(판별 근거, 개수, 단계별 시간, 자원), 그래프(연결 관계 배치, 노드 클릭 시 원본 강조), 직렬화(LLM 입력 텍스트, 복사), 색인(완전 일치·BM25·표 행·임베딩), 표·본문, 질의(부분 그래프).

## 파일

| 파일 | 내용 |
|---|---|
| `server.py` | 표준 라이브러리 HTTP 서버. 업로드, 작업 대기열, 진행 상태, 질의, 작업 파일 제공 |
| `pipeline.py` | 처리 묶음과 자원 제어 |
| `static/index.html` | 화면. 외부 라이브러리 없음 |
| `jobs/` | 작업별 입력·결과(실행 시 생성, 저장소 제외) |
